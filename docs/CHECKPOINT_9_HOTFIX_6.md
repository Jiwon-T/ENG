# 중단 상태·선생님 담당 연결 구간

체크포인트 9와 기존 핫픽스 1~5(일지 엑셀 포함)를 모두 포함합니다. 이번 요청의 1번 구간만 구현했습니다.

## 중단 상태 점검

기존 점검은 반의 상태를 확인하지 않고 소속반에 연결된 학생 수강 상태가 등록이 아니면 오류를 만들었습니다. 이제 같은 과목의 수강과 반이 모두 중단이면 소속반과 이전 담당 관계를 퇴원 이력으로 보존하며 CLASS_ASSIGNMENT_MISMATCH를 만들지 않습니다. 진행 중인 반에 중단 수강이 연결됐거나 등록 학생의 반 담당과 수강 담당이 다르면 계속 확인 항목으로 표시합니다. 실제 원본 누락·중복 수강·잘못된 날짜·다른 학생 리포트 연결 검사는 중단 학생에게도 유지합니다. 점검 결과에 반 상태도 표시합니다.

## 실제 노션 구조 확인

읽기 전용으로 DB_수강, DB_선생님, DB_반 관리와 영어 이지원T 페이지를 확인했습니다.

- DB_수강의 영어/수학/국어/과학/한국사 담당은 모두 DB_선생님으로 연결되는 relation입니다.
- DB_선생님의 담당 과목은 5개 과목을 포함한 multi_select이며 상태는 재직/휴직/중단/테스트 선택입니다.
- DB_반 관리 상태는 대기/진행 중/중단 status입니다.
- 영어 이지원T 페이지는 DB_선생님에 속하며 재직·영어 상태입니다.

이 구조에는 담당 연결을 위한 속성 추가가 필요하지 않습니다. 실제 서버의 기존 실패 요청에 저장된 오류 코드는 배포 후 개선한 목록에서 확인합니다. 운영 서버의 해당 요청을 재실행하거나 운영 데이터를 수정하지 않았습니다.

## 담당 범위 사용법

관리자 설정 → 선생님 담당 범위 목록에서 **조회·수정**을 누릅니다. 선생님 이름·학생·과목·마지막 노션 반영 상태와 실패 이유를 함께 보여줍니다. 연결 페이지 ID, 학생별 과목 체크, 저장을 제공합니다. **현재 노션 담당 불러오기**로 실제 담당을 확인해 편집란에 가져오고, 확인 후 저장하면 앱 목록도 맞춰집니다. 목록의 범위는 앱 저장 값이고 반영 상태는 마지막 요청 결과이므로 외부 노션 수정 후에는 이 버튼으로 확인합니다.

반영 실패·대기는 **저장한 범위 다시 반영**으로 처리합니다. 부분 반영 또는 결과 불명인 요청은 입력 변경을 잠시 막고 원래 요청을 먼저 복구합니다. 노션 쓰기를 시작하기 전 실패한 새 요청은 페이지 연결 등을 바로 수정할 수 있습니다. 예전 버전의 실패는 쓰기 여부를 알 수 없어 보수적으로 복구를 먼저 요구하지만, 선생님 페이지 미연결 등의 명확한 사전 실패는 연결 수정이 가능합니다.

계정이 최고 관리자이면 교사 역할 필터에서 누락되던 설정 목록에 포함합니다. 이 계정의 담당 범위를 저장해도 관리자 역할을 교사로 바꾸지 않습니다. 신입생 폼의 배정 목록·입학 상담 연동은 별도 3번 구간에서 다룹니다.

## 실패 복구 개선

기존 저장은 실패한 요청을 다시 저장할 때 previousNotionAssignment를 현재 앱 범위로 덮어써서, 이미 제외한 학생의 담당 해제를 재시도에서 놓칠 수 있었습니다. 원래 이전 범위를 성공할 때까지 유지합니다. 조회·저장 요청의 수정 차수와 활성 임대 검사, 노션 쓰기 전 임대 갱신, 결과 저장의 임대 소유 검사로 동시 요청과 늦은 응답을 차단합니다. 기존 재시도 버튼도 같은 보호를 사용합니다.

변경 대상 전체의 수강 행·학생 연결·담당 관계 종류·DB 연결 대상·담당 과목 옵션을 먼저 검사합니다. 쓰기 직전에 담당 관계를 다시 읽고 해당 선생님만 추가·제외하며 공동 담당은 유지합니다. 변경 없는 속성은 쓰지 않습니다. 다른 학생의 시작일·중단일·수강 상태·반은 변경하지 않습니다. 반 담당과 학생 수강 담당의 불일치는 점검에서 표시하며 해당 반 담당을 별도로 관리해야 합니다.

페이지 미연결, 잘못된 DB, 중단/휴직 선생님, 누락/중복 수강, 속성 종류/연결 대상 불일치, 인증·공유 권한·주소·요청 제한을 각각 안내합니다. 같은 노션 선생님 페이지를 다른 앱 계정에도 연결하는 요청은 차단합니다. 현재 공용 main 학원 DB 연결에 적용하며 다른 학원의 임의 담당 변경은 수행하지 않습니다.

## 검증 및 다음 작업

테스트 398개, 타입 검사, 빌드, native Node 서버 import 통과. 중단 정상 이력/활성 반 불일치, 공동 담당 보존, 중복 수강 사전 차단, 속성 사전 진단, 부분 실패 후 원래 범위 복구, 활성 임대/다른 학원/중복 선생님 연결 차단, 관리자 역할 보존과 목록 표시를 검증했습니다. 노션 관계 수정에는 원격 compare-and-swap이 없어 앱 밖에서 동시에 담당을 변경하면 다시 불러와 확인해야 합니다.

실제 운영 데이터·노션 속성 변경, 배포, 문자 발송, Make 변경은 하지 않았습니다. ZIP을 전달한 뒤 멈춥니다. 다음 구간은 2번 일정 장소 선택지이며, 이후 3번 입학·상담 원서와 배정 목록, 4번 학생 카드 모달·탭을 순서대로 진행합니다.
