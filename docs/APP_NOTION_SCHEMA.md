# 앱–노션 전환: 실제 스키마 확인 기록

2026-10-05 Notion 연결로 조회했다. 체크포인트 3에서 학생 관리에 학교·앱 등록 ID, 수강에 앱 등록 ID rich_text 속성을 추가했다. 기존 행 내용과 Make 시나리오는 수정하지 않았다. 앱 동기화 시에도 필요한 속성 타입과 학생 관계형 대상을 검증한다.

## 체크포인트 4: 담당·반 최초 배정

- DB_선생님: 선생님(title), 담당 과목(multi_select), 상태(select: 재직/휴직/중단/테스트). 재직 중이며 서버 teacherWorkspaceAccess의 같은 학원 활성 교사 계정과 연결된 선생님만 배정 가능하다.
- DB_반 관리: 수업명(title), 과목(select), 학원(rich_text), 상태(status: 진행 중/중단), 담당 선생님(relation), 대상 학생(relation). 학원 main, 진행 중, 과목·담당이 일치하는 반만 신입생에 배정한다.
- DB_학생 관리 소속반 ↔ DB_반 관리 대상 학생: 양방향 관계. 생성 전에 REST relation.dual_property.synced_property_id를 양쪽에서 검증한다. 학생 생성의 소속반만 기록해 반의 다른 학생을 덮어쓰지 않는다.
- DB_수강: 과목 담당 relation은 DB_선생님을 가리켜야 한다. 선택한 teacherUid는 서버에서 페이지 ID로 해석하며 브라우저가 제출한 임의 Notion 선생님 ID를 받지 않는다.
- 이번 단계는 신규 등록의 최초 배정만 포함한다. 기존 학생의 정보·담당·반 수정 및 보호자 번호/PIN 갱신은 다음 단계다.

## 체크포인트 5: 학생 기본 정보 수정

학생 관리의 학생(title)·학교(rich_text)·학년(select)·학생연락처/보호자연락처(phone_number)·보호자이름/학생 호칭/납부기한(rich_text)·수강료(number) 중 변경한 속성만 수정한다. 기존 제목은 그대로 읽으며 이름/학교/학년을 추정해 분해하지 않는다. 수강/담당/소속반과 문자 템플릿·등록 ID는 이번 기본 정보 수정에서 변경하지 않는다.

서버 teacherStudentEdits는 학생 페이지 ID의 해시별 단일 진행 중 수정과 복구 상태를 보관한다. 연락처 변경 요청을 접수하는 거래에서 기존 reportSlugs의 authVersion을 1회 갱신하고 PIN을 잠근다. 원격 저장 확인 뒤 기존 PHONE_PIN_PEPPER로 새 HMAC PIN 해시를 저장한다. 새 리포트 발급 거래는 연락처 반영 중 잠금과 읽어 온 Notion 페이지 편집 시각을 함께 확인한다. 이 서버 보조 상태를 브라우저에서 직접 읽거나 쓰지 않는다.

## 체크포인트 6: 기존 학생 수강·담당·소속반 변경

DB_수강의 선택 과목 상태·시작일·중단일·담당 관계만 PATCH한다. 담당은 기존 관계에서 명시적으로 제외한 ID만 제거하고, 서버가 해석한 같은 학원 재직 교사의 ID를 중복 없이 추가한다. 다른 과목은 변경하지 않는다.

DB_학생 관리의 소속반은 다른 과목 반을 보존하고 선택 과목의 최종 반 관계만 교체한다. 양방향 관계 속성 ID와 DB를 검증하며 반 대상 학생은 직접 PATCH하지 않는다. 등록상태·강의명은 전체 과목 상태를 합산하고 수강시작일은 과목 시작일의 최솟값으로 갱신한다. 수강/학생의 앱 등록 ID와 학생·리포트 식별 연결은 보존한다.

teacherStudentEnrollmentEdits는 서버 전용 상태이며 단계별 원격 시도·확인과 요청 lease를 보관한다. 연락처 수정 상태인 teacherStudentEdits와 구분한다. 기본 정보/수강 변경의 외부 동시 편집은 페이지 편집 시각으로 검출한다. 부분 반영 후 불명확하거나 외부 충돌이 있으면 자동 롤백·덮어쓰기하지 않는다.

## 체크포인트 7: 직접 반영과 저장 복구

중앙 DB_일정표(3430f1a4-9dde-4b4c-a5cf-0d11b913b38c)의 기존 속성을 사용한다. 앱 기록 ID·일정명·과목·대상 학생·담당 선생님·날짜 및 시간·일정 종류·일정 상태·장소·안내 내용·요일·반영 상태를 기록하며 반영 요청 수식은 앱 반영의 필수 속성이 아니다. 개인 앱 일정은 studentSchedules에 직접 저장한다.

수업일지·성적·일정 초안 문서의 notionWrite에는 불변 revision별 속성·원본 DB·원격 페이지 ID·예상 시각·요청 시도·확인 완료·lease가 추가되었다. 공개 DTO에는 이 내부 상태를 전달하지 않는다. scheduleSyncStates는 서버 전용 원본 버전·앱 관리 소유권 상태다. Firestore 규칙에 직접 접근 차단을 추가했다.

기존 Make 웹훅은 유지하되 앱 관리 일정/일지는 본문을 적용하지 않고 성공 응답으로 무시한다. 미전환 원본은 sourceUpdatedAt 순서로 반영한다. 성적 웹훅은 기존처럼 실제 Notion 페이지를 조회하고 원본 버전을 검증한다.
