# 체크포인트 10 B hotfix 1 — 선생님방 입력과 동시 작업

## 이번 범위
사용자가 확정한 핵심 세 가지와 저장 왕복 개선만 적용했습니다. 이전 A/hotfix/B 변경을 모두 유지합니다.

- 여러 학생 모달의 학생 칩에 X를 추가했습니다. 작성 목록에서 해당 행만 제외하며 저장된 앱/Notion 기록을 삭제하지 않습니다. 수정한 입력은 확인 후 제외하고, 처리 중인 행은 제외할 수 없습니다.
- 성공 알림은 4.5초, 오류·대기 알림은 9초 후 사라집니다. 탭·학생·편집 대상이 바뀌면 이전 알림을 제거하며 닫기 버튼도 제공합니다. 저장·반영 상태와 실패 내역은 기록/작업 상태에 남습니다.
- 전체 선생님방 잠금을 작업 대상별 잠금으로 바꿨습니다. 같은 기록의 중복 요청은 막고 다른 기록/탭 작업은 진행할 수 있습니다. 모달을 닫아도 진행 중 요청을 유지합니다. 여러 학생 작성에서는 처리 중인 학생만 잠급니다.
- 일지·일정·성적 저장 응답에 실제 커밋된 기록을 담습니다. 일지 저장 후 별도 managed-record 조회와 목록 재조회 대신 응답으로 화면을 갱신합니다. 저장만 하는 일지 흐름은 한 번의 저장 요청으로 완료됩니다. 반영은 저장이 필요한 경우 저장 후 별도 반영 요청을 유지합니다.
- 입력 스냅샷·편집 세대·기록 revision 검증을 유지해 늦은 응답이 다른 학생의 입력을 덮어쓰지 않도록 했습니다. 계정 변경 중인 요청도 차단합니다. 서버 권한·충돌·복구 규칙을 유지합니다.

## 검증
전체 테스트 493개, 타입 검사, native 서버 import, 프로덕션 빌드 통과. 기존 번들 크기 및 Firebase mixed import 경고는 남습니다.
추가 테스트는 다른 작업의 동시 실행, 동일 기록 중복 차단, 작업 초기화, 학생 행 제외, 늦은 revision, 저장 후 반영 순서, 계정 전환, 저장 응답의 canonical 기록과 불필요한 추가 읽기 제거를 확인합니다.
로컬 브라우저에서는 실제 컴포넌트와 가짜 학생/응답을 사용했습니다. X로 한 학생만 제외, 반영 대기 중 모달 닫기 및 다른 일정 입력, 상황 변경 후 알림 제거를 확인했고 콘솔 오류는 없었습니다.
운영 환경 배포·실제 Notion 저장·실제 문자 발송은 수행하지 않았습니다.

## 배포 후 확인
1. 여러 학생 두 명을 추가하고 한 명의 X를 누릅니다. 해당 학생만 빠지고 기존 일지 조회 기록은 유지되는지 확인합니다.
2. 수정 중인 학생을 제외하면 확인 안내가 뜨는지 확인합니다.
3. 일지 반영 직후 모달을 닫고 다른 학생 일지/다른 일정 입력을 진행합니다. 처리 중 기록은 중복 반영되지 않고 결과는 상태에 표시되는지 확인합니다.
4. 먼저 반영한 학생의 응답이 돌아와도 현재 학생의 입력이 유지되는지 확인합니다.
5. 성공 알림이 잠시 후 사라지고 탭이나 편집 대상 변경 시 이전 알림이 표시되지 않는지 확인합니다.
6. Notion 실패 시 기록의 대기/실패 상태와 복구 동작을 확인합니다.

## 남은 범위
이번 변경은 브라우저에서 진행 중인 요청을 유지하는 방식이며 서버의 영구 비동기 큐를 추가하지 않았습니다. 브라우저 종료/네트워크 유실은 기존 기록 상태 확인·복구 경로를 이용합니다.
칩 입력, 고정 액션바, 자동 회차 변경, 자동 임시저장, 다음 학생 자동 선택, 레이아웃 개편, 선행 로딩, 서버 최소 인스턴스, 유료 예약 백업은 이번 범위에서 제외했습니다.
Bati 실제 본문 매핑·보안 헤더·성공 응답은 여전히 미확인입니다. 실제 발송은 기존대로 차단하며 B 문서의 확인 절차를 유지합니다. C/Make 중단은 진행하지 않았습니다.
