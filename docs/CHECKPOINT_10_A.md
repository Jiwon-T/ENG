# 체크포인트 10 A — 연결·권한·중복·실패 복구

2026-10-06. 누적 기준: checkpoint 9 hotfix 10 → 단어장 디자인 hotfix 11 → 이번 A. 체크포인트 10 전체 완료를 뜻하지 않습니다. 다음 구간은 사용자 재개 후 B이며 운영 Make는 유지합니다.

## 수정

- Firebase 토큰 취소·계정 비활성 상태를 서버에서 확인합니다. 관리자도 명시적으로 비활성화한 작업 계정은 차단합니다. 학원 식별자가 없는 계정과 타 학원 원본 접근을 차단하고 저장된 담당 범위도 현재 학생 소속으로 검증합니다.
- 수업일지 앱 리포트의 트랜잭션에서 최신 원본 revision 및 학생의 현재 학원/활성 소속을 다시 확인합니다. 늦게 끝난 작업의 성공·실패가 더 최신 저장 상태를 덮어쓰지 않도록 성적/일정/일지 최종 상태 갱신도 revision으로 보호합니다.
- 앱에서 소유한 성적은 늦은 Make/Notion 원시 동기화가 덮어쓰지 못합니다. 첫 리포트 생성 전의 빈 구간도 원본 앱 기록 ID와 저장 시도 journal로 보호합니다. Notion 재조회 값이 제출한 속성과 다르면 리포트 투영 전에 충돌로 중단합니다.
- Notion 목록 새로고침으로 앱에 저장한 값이나 비교 기준 시각을 덮어쓰지 않습니다. 기존 성적 편집은 새 원본으로 재수입하지 않고 같은 앱 draft/Notion 페이지를 유지합니다.
- 성적 삭제를 추가했습니다. 원본은 휴지통, 앱 성적/리포트는 보존용 tombstone으로 숨깁니다. 삭제 의도·같은 원본 ID·lease를 보존해 응답 유실 후 결과를 확인합니다. 원본 학생/DB/기록 ID/수정 시각과 리포트 소유권이 다르면 중단합니다. 원본 삭제를 아직 시도하지 않은 실패에만 삭제 요청을 취소할 수 있습니다. Notion에서 읽은 성적은 먼저 저장해 앱 revision을 확보한 뒤 삭제합니다.
- 수업일지에 있던 앱/Notion 비교 복구를 성적·일정에도 추가했습니다. 최신 스냅샷 토큰과 revision으로 다시 확인하고 같은 원본 ID에 선택한 내용을 반영합니다. 학생·과목 변경 또는 실행 중/삭제 요청 중에는 차단합니다. 선택 자체는 앱 draft를 갱신하며, 이어지는 반영은 기존 안전한 publish 경로를 사용합니다.
- 무변경 운영 점검에 성적·일정, 원본별 중복, 앱 리포트와 학생 식별 불일치, 삭제 대기, 관계 없는 과거 기록을 추가했습니다. 공유 학원 설정/개별 선생님 설정/저장 journal의 수업일지 DB를 포함합니다. 조회 실패는 검사 미완료로 표시합니다. 취소된 일정의 보존 이력과 정상 퇴원 이력을 중복/오류로 분류하지 않습니다.

## 검증

전체 회귀 테스트 443개 통과. 타입 검사, native Node 서버 import 검사, 프로덕션 빌드 통과. 기존 Firebase 혼합 import 및 큰 번들 경고는 남아 있습니다.

모의 Firestore/Notion 테스트: 소유권/학원/계정 비활성, 교사 본인 일지·내보내기와 관리자 필터 권한, 학생/학부모 공개 범위와 PIN 기존 회귀, 0점 보존, 생성/수정/삭제, 부분 실패·응답 유실·중복 요청·재시도, 같은 원본 사용, 늦은 Make 방어, 다중 일정 제외/재포함/취소, 성적 삭제 복구, 세 종류 충돌 선택과 오래된 스냅샷 차단. 새 테스트가 코드·모의 환경의 검증이며 실제 운영 발송/쓰기의 증거는 아닙니다.

운영 Notion은 읽기만 수행했습니다. 상세 수량·학생별 발견 사항은 CHECKPOINT_10_A_OPERATIONAL_READ.md를 확인하세요. 운영 Firebase 자격 증명/계정·매핑·리포트 컬렉션은 조회하지 못했습니다. 따라서 실제 운영 계정과 리포트 URL의 양방향 연결, 운영 Firestore 중복 여부는 아직 확정할 수 없습니다. 배포와 실제 화면 클릭은 사용자 확인 대상입니다.

## 기존 기록과 확인된 차이

421개 통과 기록은 hotfix 10 기준입니다. hotfix 11 디자인은 그대로 포함하고 이번 테스트는 443개입니다. 과거 문서의 성적/일정 전환 구현 사실과 별개로, 실제 코드는 앱 소유 성적의 첫 투영 전/후 원시 동기화 방어와 성적 삭제, 성적·일정 비교 복구가 부족해 이번에 보강했습니다. 기존 integrity audit는 성적·일정을 충분히 포함하지 않아 확장했습니다. 실제 운영 수업일지 중 781행은 학생 관계가 없어 현재 단일 학생 투영 기준으로 안전하게 학생을 확정할 수 없습니다.

## 사용자 배포 후 A 확인

1. 관리자/원장으로 무변경 연결 점검을 실행하고 검사 미완료·학생 이름·자료 종류·조치 안내를 확인합니다. 운영 계정/리포트 매핑 결과는 이 점검에서 확인합니다.
2. 일반 선생님으로 본인 일지 조회/수정/삭제/엑셀 내보내기, 타인 일지 차단 및 선생님 선택 미노출을 확인합니다. 비활성 계정과 타 학원 요청도 차단되는지 확인합니다.
3. 테스트 학생의 기존 URL/PIN을 기록하고 일지·성적·일정을 생성/수정합니다. 앱 리포트 완료와 Notion 대기를 각각 확인합니다. 저장 결과 재시도 후 원본 페이지·리포트 ID가 동일하고 행이 늘지 않는지 확인합니다.
4. 다중 학생 일정의 일부 제외/재포함/전체 취소, 실제 장소 옵션을 확인합니다. 성적 삭제는 별도 테스트 기록으로 진행하고 취소 이력과 원본은 보존되는지 확인합니다.
5. 테스트 원본을 Notion에서 수정해 충돌을 유도하고 앱/Notion 선택 복구가 같은 페이지를 사용하는지 확인합니다. 비교 후 Notion을 다시 수정하면 오래된 선택을 거부해야 합니다.
6. 학생·학부모 화면에서 공개 범위와 PIN을 확인합니다. 이름·학생 ID·URL/PIN이 바뀌면 중단하고 결과를 알려 주세요.

실제 데이터 삭제/병합, 배포, 문자 발송, Make 중단은 수행하지 않았습니다. 기존 공동 담당/다른 과목/리포트 인증과 상담·입학 원서 구조를 유지했습니다. 복제 일지 리셋은 구현하지 않았습니다. Bati 규약은 B에서 확인하며 추정하지 않습니다.
