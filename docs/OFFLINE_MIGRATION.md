# 화면 없는 일회성 이전 도구

작업 폴더: checkpoint-10-a/ENG. ENG-repo와 외부 GitHub 폴더는 읽기만 했습니다.

## 실행 범위
문자 템플릿 → 학생·선생님·수강 → 교재·반·정규 시간표 → 과거 성적 → 일정 → 일지 순으로 실행합니다. 필요한 종류만 --kinds로 선택할 수 있습니다. 새 계정/PIN 생성, 문자 발송, Make 변경, 앱 전용 authority 활성화는 실행하지 않습니다.

화면이나 웹 요청을 거치지 않고 Node 프로그램이 기존 이전 서버 함수를 직접 호출합니다. 브라우저 종료는 영향을 주지 않습니다. 컴퓨터/프로세스가 종료되면 기존 Firestore 진행 위치에서 다음 실행 시 재개합니다. 프로그램이 꺼져도 계속 진행하는 별도 서버 서비스는 아닙니다.

기본 조회 배치는 50건, --batch 100으로 늘릴 수 있습니다. 템플릿·학생 자료는 최대100, 일지·성적은 최대50, 반·시간표는 관계 조회와 3분 잠금을 고려해 최대10입니다. 기존 화면의 배치 크기는 바꾸지 않습니다. Notion 조회는 시작 간격350ms로 직렬화하고 단순429 및 일시적인 서버 오류를 제한 재시도합니다. Notion 자체 제한을 우회하지 않습니다.

Firestore 저장은 기존 권한·동시 수정·연결 검사와 rollback을 보존하는 개별 트랜잭션을 재사용합니다. 검증을 없애는 일괄 덮어쓰기보다 안전합니다. 실제 속도/청구액은 운영 실행 전에는 측정하지 못했습니다.

## 일지 날짜
2026-09-20 포함 이후만 대상입니다. Notion 날짜 속성을 읽을 수 있으면 서버 날짜 필터를 쓰고, 각 행에서도 다시 검사합니다. 이전 날짜 또는 날짜 없는 일지는 이전하지 않습니다. 원본은 삭제하지 않습니다.

일지는 기존 lessonSourceRecords 검증 저장본에 먼저 적재합니다. 기존 teacherLessonDrafts/lessonReports는 이 단계에서 덮어쓰지 않습니다. 보류·대조·별도 앱 전환이 끝나기 전까지 공개 화면 이전 완료라고 주장하지 않습니다.

## 결과와 보류
콘솔에는 종류·단계·건수·오류 코드만 출력합니다. 학생 이름·본문·전화번호·키는 출력하지 않습니다. 종료코드0은 해당 도구의 점검/처리 완료이며 앱 전환 완료가 아닙니다. 2는 중단/보류, 1은 설정/초기화 실패입니다.
한 원본 연결이 막혀도 독립적인 종류와 반/교재 원본은 계속 처리합니다. 보류 자료는 기존 관리 도구에서 상세 확인합니다. 날짜가 오래된 자료/공개 식별자 충돌/계정·작성자 연결은 자동 무시하지 않습니다. 별도 전환과 원본 편집 중단 확인은 기존 관리자 절차를 유지합니다.
