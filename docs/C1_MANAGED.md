# C-1 두 번째 묶음 — 반·정규 시간표·교재

2026-10-08. 앞 C-1 학생/수강/권한 묶음에 반·시간표·교재의 영구 저장 및 앱 수정 경로를 추가합니다. 운영 이전/배포는 실행하지 않았습니다.

## 구현 범위

- 기존 teacherClasses/teacherCurricula를 재사용합니다. 원본 페이지 ID와 앱 ID가 다르면 기존 Notion 연결 또는 앱 기록 marker로 연결하며 원본별 academyManagedSources에는 해당 저장본의 포인터만 둡니다. 사용자별 원본 복제는 만들지 않습니다.
- 관리자 설정의 ‘반·정규 시간표·교재 이전’은 처음에 닫혀 있고 mount 시 요청하지 않습니다. 원본은 현재 서버 설정에서만 선택하며 브라우저가 임의 DB를 지정할 수 없습니다.
- 교재 먼저, 반 다음으로 원본 1건씩 가져옵니다. 반에서는 연결된 교재와 정규 시간표를 검증합니다. 잘린 관계는 끝까지 읽고, 14개를 넘는 시간표/불완전 관계/미이전 교재는 오류로 멈춥니다. 임의로 잘라 저장하지 않습니다.
- dry-run은 내용 쓰기 0, cursor로 다음 원본을 확인합니다. 실제 가져오기/최종 대조는 기존 앱 미완료 저장·삭제·소유자/학원/과목 충돌을 덮어쓰지 않습니다. 페이지 진행 위치는 내용 처리 성공 뒤 전진합니다.
- 최종 대조는 Notion 수정을 중단한 뒤 전체를 다시 읽습니다. 시간표 자체 변경이 반의 수정 시각에 반영되지 않을 수 있으므로 이 묶음에서는 마지막 변경 시각만 믿고 반을 건너뛰지 않습니다.
- 종류별 전체 최종 대조 완료, 15분 이내 확인, 잠금 없음, 미완료 변경 없음, 교재/반 참조 대조 후 academyClassAuthority/main을 확정합니다. 중간 cursor나 오래된 검증으로 전환하지 않습니다.
- 반·교재는 sourceMode=firestore, notionSyncRequired=false, ‘앱 저장 완료’ 상태입니다. 저장 시 Notion을 호출하지 않습니다. 새 공통 계획은 Notion 페이지 ID 없이 선택할 수 있습니다.
- 반 편집은 기존 학생/과목/요일/시간/교재 값 schema, 소유/권한 검사, revision 검사를 유지합니다. 학생 반 관계와 기록 이력을 같은 트랜잭션으로 갱신합니다. 삭제는 기존 confirm 이후 archive로 처리하며 기록/원본 연결을 물리 삭제하지 않습니다.
- 이전된 반/교재 조회는 이전 Notion 캐시를 재사용하지 않고 최신 앱 저장본을 읽습니다. 전환 전 시작된 legacy 저장·삭제·재반영도 경계 검사로 원본 쓰기를 막습니다.

## 순서

1. 기존 ‘학생·선생님·수강 이전’의 대조를 준비합니다. 운영 전환은 아직 하지 않습니다.
2. 교재→반/시간표 dry-run과 최초 가져오기를 모든 cursor가 끝날 때까지 수행합니다.
3. Notion 직접 수정을 중단하고 교재→반/시간표 최종 대조를 모두 완료합니다. 앱/원본 연결과 필드 값을 별도로 확인합니다.
4. ‘반·교재 앱 저장본 확정’은 반의 조회 경계를 기록합니다. 이 단계만으로 수정은 활성화하지 않습니다.
5. 학생/수강/담당 권한의 최종 대조와 전환을 완료하면 반 수정도 Firestore에서 동작합니다. 전체 운영 전환은 신규 등록 등 남은 필수 경로를 마무리한 후 진행합니다.

원자적 전환은 종류별 100개, 일반 목록은 500개 상한입니다. 초과 시 중단하며 분할 전환이 필요합니다. 현재 일지/성적/일정과 실제 문자 전체가 독립 운영된다고 주장하지 않습니다.

## 남은 작업

앱 전용 신규 학생 등록은 다음 묶음입니다. 기존 등록이 Notion 페이지 ID를 먼저 생성하는 구조이므로 app-origin ID와 기존 출처 ID를 구분하고, 계정·내부 ID·담당/반 연결·등록 이력을 원자적으로 생성하는 경로가 필요합니다. 현재 전환 후 legacy 신규 등록을 Notion에 실행하지 않는 차단은 유지합니다. 이 조건을 우회해 실운영을 먼저 전환하지 않습니다.

일지의 저장/학부모 공개와 Notion 동기화 분리, 일정·성적·문자/리포트의 남은 의존도 제거는 후속입니다. Make·실제 문자 발송은 변경/실행하지 않았습니다.

## 검증·복구

- 모의 검증: dry-run 0쓰기, 원본/앱 ID 유지, 시간표/교재 연결, Notion 차단 조회·반/계획 수정, 학생 연결 변경, 소유자/버전/중복 슬롯 거부, commit 실패, 삭제 및 이력, 최종 대조 완료 전 확정 거부.
- 이전/관리 컬렉션 client read/write deny와 이력 payload 인덱스 제외를 추가했습니다. 클라우드 규칙/인덱스 적용은 사용자가 합니다.
- 기존 로딩 테스트에 전환 checkpoint 읽기 1개를 반영했으며, 학생/일정/설정의 불필요한 로딩이 없다는 검사는 유지했습니다.
- 이력은 복구 자료입니다. 반/계획 전체 선택 복원의 관리 화면, 독립 백업/PITR 설정은 아직 구현/활성화하지 않았습니다. 문제가 생기면 앱 최신 자료를 보존하고 Firestore 경로를 지원하는 정상 버전/forward fix로 처리합니다. 오래된 Notion으로 단순 복귀하지 않습니다.
- 실제 운영 자료·클라우드·브라우저·비용은 미검증입니다. 일지 폼 내부 배치는 변경하지 않았습니다. 기존 빌드 경고는 그대로입니다.

검증 결과: lint, 전체 테스트 612개, build, 일반 Node ESM import 통과. 최종 대조 cursor/ready 경계와 전환 전 시작된 legacy 쓰기 차단을 포함합니다. 실제 운영 이전을 실행하지 않았습니다.
