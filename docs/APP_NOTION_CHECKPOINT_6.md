# 앱–노션 전환 재개 기록: 체크포인트 6

기준: 사용자가 첨부한 ENG-app-notion-checkpoint-5(1).zip 전체 코드에 누적 적용했다. 체크포인트 1~5와 수업 내용 필수·특이사항 연동·반영 중 팝업 닫기 수정은 포함되어 있다. 이전 기록은 APP_NOTION_CHECKPOINT_5.md에 보관했다.

## 이번 단계 완료

- 학생 관리 카드에 관리자·원장 전용 **수강·담당·반 관리** 팝업을 추가했다.
- 기존 학생의 수강 상태(등록/대기/중단), 과목별 시작일·중단일, 담당 추가·명시적 제외, 소속반 선택을 과목 하나씩 변경한다.
- 담당 추가는 같은 학원의 활성 교사 계정과 재직 중인 Notion 선생님 페이지, 담당 과목을 서버에서 확인한다. 브라우저가 임의 선생님 페이지를 추가할 수 없다. 기존 공동 담당은 제외 체크를 하지 않으면 유지한다.
- 선택하지 않은 과목의 수강·담당·반을 유지한다. 중단·대기는 해당 과목 반을 모두 해제해야 저장할 수 있으며 과목별 중단일을 검증한다. 전체 등록상태·강의명은 과목 상태를 합산하고 수강시작일은 기록된 과목 시작일 중 가장 이른 날짜로 갱신한다.
- 기존 학생·수강 페이지 ID, 앱 등록 ID, 학생 계정·내부 식별 ID, 리포트 주소·PIN·인증 버전을 유지한다. 이 기능은 보호자 연락처를 수정하지 않는다.
- DB_수강은 학생당 정확히 한 행이어야 한다. 중복·연결 없음·다중 학생 관계·잘린 관계·다른 원본 DB는 자동 선택 없이 오류로 처리한다.
- 학생 소속반 ↔ 반 대상 학생의 양방향 관계 스키마를 확인하고 **학생의 소속반만 PATCH**한다. 공유 반의 학생 명단은 읽어 병합하거나 PATCH하지 않는다. 기존 연결에서 제외되는 반은 학생 관계 제거를 통해 Notion 양방향 관계로 해제된다. 실제 양방향 자동 반영은 사용자 배포 확인 대상이다.
- 새 반은 학원·과목·진행 중 상태·저장 후 담당 관계가 일치해야 한다. 기존 반이 보관된 경우에도 읽어 제외할 수 있다.
- 기존 workspace API에 GET student-enrollment, POST save-student-enrollment, POST discard-student-enrollment를 추가했다. Vercel 함수와 비밀 환경변수를 추가하지 않았다.
- 원장은 같은 학원의 활성 학생만 변경할 수 있다. 관리자는 명시적으로 다른 학원 소속인 학생을 수정할 수 없다. 일반 교사는 이 상세 변경 API를 사용할 수 없다.
- teacherStudentEnrollmentEdits에 학생별 단일 요청, 입력, 예상 편집 시각, 단계별 PATCH 시도·확인, 3분 lease를 서버에 저장한다. Firestore 직접 읽기·쓰기는 금지했다.
- 단계는 수강 행 → 학생 명부 → 기존 앱 수강 자료 반영이다. 저장 전/후 원본·편집 시각·실제 값을 확인한다. 수강 반영 후 학생 명부 갱신 실패 시 수강 PATCH를 반복하지 않는다. 앱 반영 실패도 현재 Notion 자료를 읽어 복구한다.
- 응답 유실 후 대상 값이 이미 일치하면 같은 UUID로 확인하고 다음 단계를 진행한다. 같은 UUID의 다른 입력, 다른 미완료 요청, 아직 살아 있는 lease를 거절한다. lease를 넘겨받은 새 요청이 있으면 오래된 실행의 앱 반영 거래를 차단한다.
- 반영 결과가 불명확하고 값이 일치하지 않으면 재PATCH·취소를 차단한다. 실제 원격 상태 확인이 필요하다. 아무 단계도 반영하지 않은 확정 실패만 취소할 수 있다. 부분 반영은 취소나 새 요청으로 대체하지 않고 기존 요청으로 완료해야 한다.
- 학생 명부 갱신 전에 완료된 수강 단계의 편집 시각을 다시 확인한다. 사이에 다른 과목을 수동 수정했으면 이전 수강 상태로 만든 요약으로 덮어쓰지 않고 충돌을 안내한다. 이 경우 운영 기록 확인·정합성 복구가 필요하며 자동 롤백은 하지 않는다.
- Notion은 조건부 원자 PATCH를 제공하지 않으므로 최종 조회와 PATCH 사이 외부 편집 경쟁을 완전히 차단할 수는 없다. 충돌 시 자동 덮어쓰기를 피한다.
- 기존 권한 조회는 완료된 담당 관계를 매 요청 다시 확인한다. 영어 담당 제외 후 영어 범위는 사라지고 수학 공동 담당은 유지되는 실제 기존 권한 함수 경로를 검증했다.
- 팝업을 닫거나 계정을 바꾸면 늦은 응답을 무시한다. 다시 열면 미완료 요청을 복구한다. 브라우저 영구 저장소에 학생 상세 정보를 보관하지 않는다. 목록 갱신은 계정·요청 세대로 보호한다.

## 검증

전체 테스트 **290개 통과**, TypeScript 검사 및 프로덕션 빌드 통과. 빌드에는 기존 큰 번들 경고가 남아 있으며 실패는 아니다.

거래형 Firestore와 모의 Notion 응답으로 과목 분리, 공동 담당 유지/제외, 반 교체/제외, 리포트 식별·인증 보존, 응답 유실, 부분 실패, 앱 반영 실패, 중복 수강, 원본·권한·입력 위조, 편집 충돌, 휴직/반 중단 후 재시도 차단, 기존 교사 접근 범위 갱신을 확인했다. 실제 HTTP workspace 경로에서 일반 교사와 위조 입력이 원격 요청 전에 거절되는 것도 검증했다.

운영 Notion 자료 변경·실계정 클릭·배포·병합·문자 발송·Make 중단은 수행하지 않았다. 사용자 배포 후 학생 카드 → 수강·담당·반 관리에서 과목 하나를 수정하고 Notion 수강/학생/반의 양방향 관계와 교사 화면을 확인한다. firestore.rules의 서버 보조 문서 직접 접근 차단도 포함되어 있다.
