# 일지 조회 읽기 범위 줄이기 — 2026-10-09

기준: `c2-template-cutover`. 운영 실행·배포는 하지 않았습니다.

## 문제
- 일지 조회(관리자·원장·선생님)와 엑셀 내보내기는 날짜나 학생을 골라도 서버가 범위 안의 일지를 **전부** 읽은 뒤 걸렀습니다. 관리자는 컬렉션 전체를 읽었습니다.
- 문자 화면의 "이 학생 일지" 목록은 학생 한 명을 위해 학원 전체 일지를 읽었습니다.

## 바꾼 것
- **날짜 또는 학생을 고른 조회와 모든 엑셀 내보내기**는 그 범위만 읽습니다(`lessonReviewSlice.ts`).
  - 앱 일지: 기존 권한 범위(관리자 전체 / 원장 학원 / 선생님 본인)에 `data.date`, `data.studentKey` 같음 조건을 더해 조회합니다.
  - 전환 후 이전된 일지: `lessonSourceRecords`도 같은 조건으로 조회합니다(`readAppSourceLessons`의 선택 조건).
  - 전환 전: Notion 원본은 기존처럼 캐시된 전체 결과를 쓰고, 고른 범위로만 거릅니다(Notion 호출 횟수는 그대로).
  - **결과가 같도록 하는 장치**: 그 범위의 원본 행과 연결된 앱 일지(같은 Notion 페이지 ID, 앱 기록 번호)도 함께 읽습니다. 그래서 앱에서 날짜를 바꾼 일지, 삭제한 앱 일지, 앱 기록 번호로만 연결된 일지가 전체를 읽을 때와 똑같이 처리됩니다.
  - 같음 조건만 써서 Firestore 기본 단일 필드 색인으로 처리합니다. 새 색인을 배포할 필요가 없습니다.
  - 날짜·학생 값 형식이 틀리면 400(`INVALID_INPUT`)을 돌려줍니다.
  - 날짜를 골라도 "작성자 선생님" 선택지에는 학원의 모든 선생님이 그대로 나옵니다(관리자·원장).
- **문자 화면 일지 목록**: 그 학생의 일지만 조회합니다. 하이픈이 있는 ID와 없는 ID를 모두 확인하고, 학원 확인은 서버에서 계속합니다.
- 아무 조건 없이 보는 전체 목록은 그대로입니다. 전체 건수와 정렬에 모든 일지가 필요하기 때문입니다.

## 검증
- lint 통과, 테스트 710/710, build 통과, Node 서버 import 통과.
- 새 `tests/lessonReviewSlice.test.ts` 3건:
  - 날짜 5개와 학생별로 **전체를 읽고 거른 결과와 범위만 읽은 결과가 같은지**, 그리고 범위만 읽을 때 문서 읽기가 더 적은지 확인합니다. 날짜를 바꾼 앱 일지, 삭제한 앱 일지, 앱 기록 번호로 연결된 일지 경우를 포함합니다.
  - 내보내기 결과, 잘못된 형식 거부, 선생님 본인 범위 유지
  - 전환 후 이전된 일지도 날짜별로 조회되는지
- 테스트용 가짜 Firestore 두 개가 `data.date` 같은 점 표기 필드를 읽도록 보강했습니다. 실제 Firestore는 원래 이 표기를 지원합니다.

## 남은 일
- 조건 없는 전체 목록은 다음 단계에서 기간 단위 쪽 나누기와 건수 집계(count)로 바꿀 수 있습니다. 화면에 날짜 범위 선택이 필요해 UX 확인이 함께 필요합니다.
- 운영 데이터 기준 읽기 수·응답 시간은 확인하지 않았습니다.
