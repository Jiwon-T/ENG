# C2 일지 앱 경로 연결 (전환 시에만 동작) — 2026-10-09

기준: `c2-lesson-cutover-switch`. 운영 전환·배포·데이터 실행은 하지 않았습니다.

## 바뀐 동작
`lessonAppActive`(검증된 전환 표식)가 켜졌을 때만 아래 경로가 앱으로 바뀝니다. 꺼져 있으면 기존 코드를 한 줄도 바꾸지 않고 그대로 씁니다. 일지 경로는 Notion을 전혀 부르지 않으며, 테스트에서 네트워크 호출 0회를 확인했습니다.

| 요청 | 전환 후 |
|---|---|
| `academy-lessons`(목록·내보내기) | Notion 대신 이전 저장본 `lessonSourceRecords`를 읽습니다. 행 형식과 보이는 범위는 같습니다(관리자 전체 / 원장 학원 / 선생님은 담당 범위 안의 본인·담당 일지). `mergeNotionRows` 규칙도 같습니다. |
| `previous-lesson`(직전 수업·회차·자습 회차) | 앱 일지 + 해당 학생 저장본만 읽습니다. `previousNotionLesson`을 호출하지 않습니다. |
| `import-source-record`(이전된 일지 수정 시작) | 그 Notion 페이지의 앱 일지가 있으면 다시 씁니다(연결된 앱 일지·앱 기록 번호 포함). 없으면 **Notion 페이지 ID를 그대로 ID로** 앱 일지를 만들고, `appProjectionId`에 기존 공개 리포트 ID를 넣습니다. |
| `save-draft` | `saveAppLesson`: 비공개 초안과 이력만 저장합니다. 공개 리포트는 그대로입니다. |
| `publish` | `publishAppLesson`: 권한·담당·학생 연결·revision을 확인하고 공개 리포트와 초안을 한 트랜잭션으로 씁니다. 기존 공개 문서 ID와 reportIdentity를 유지하고, 다시 눌러도 추가 쓰기가 없습니다. |
| `archive-lesson` | `archiveAppLesson`: 고른 공개 리포트만 지웁니다. 삭제 전 공개 내용과 초안은 `lessonAppHistory`에 남고, 이전 저장본은 보관합니다. |
| 충돌 검토·해결 | Notion 전용 기능이라 닫습니다(`LESSON_APP_ACTIVE`). |
| 반영 확인(Notion 조회) | 하지 않습니다. 앱 반영은 트랜잭션 안에서 바로 확정됩니다. |

결과가 확정되지 않은 옛 Notion 생성 요청은 `lessonWriteEvidence`로 정리합니다(같은 revision일 때만).
- 생성됨: 그 페이지를 일지에 연결합니다.
- 생성 안 됨: 남은 요청 표시를 해제합니다.
- 증거 없음: 지금처럼 `NOTION_WRITE_RESULT_UNCERTAIN`으로 막습니다.

정리할 때마다 이력을 남깁니다.

## 기타
- 이전 저장본에 `assignedUids`(담당 선생님)를 추가했습니다. 지금 화면이 담당 선생님에게도 일지를 보여 주기 때문입니다. 이 값은 행 버전에 포함되므로, 다음 이전 실행에서 기존 저장본이 한 번 다시 저장됩니다.
- `LESSON_APP_PATHS_READY = true`로 바꿔 전환 버튼을 열었습니다. 다시 잠그려면 `false`로 바꾸면 됩니다.
- 화면 문구: 전환 후에는 삭제·반영 확인창과 완료 안내에서 "노션"을 빼고 "학생·학부모 리포트"로 안내합니다(`lessonAppMode`). 이 값은 일지 화면을 불러올 때만 읽습니다.
- 미리보기 데이터를 "경로 준비 완료"로 갱신하고, 앱 브라우저 창에서 전환 버튼이 활성화된 화면을 확인했습니다(`lesson-cutover-proof/6-ready-unlocked.jpg`).

## 검증
- lint 통과, 테스트 700/700, build 통과, Node 서버 import 통과.
- 새 `tests/appLessonCutover.test.ts` 6건(workspace 실제 경로, Notion 호출 0 확인):
  - 목록·직전 수업·회차가 저장본에서 오고, 다른 선생님에게는 보이지 않음
  - 이전된 일지를 수정할 때 ID·공개 ID·reportIdentity가 유지되고, 반영 전까지 공개 내용이 그대로이며, 옛 revision은 거부됨
  - 같은 날 두 수업이 따로 공개되고, 선택 삭제·이력이 남고, 삭제 후 목록에서 숨겨짐
  - 다른 선생님의 가져오기·저장·반영·삭제가 거부되고, 충돌 기능은 닫힘
  - 미확정 생성 요청이 증거로 정리되고, 증거가 없으면 계속 막힘
  - 전환 해제 후 기존 경로로 돌아가고 앱 자료가 보존됨
- 기존 테스트 2개는 전환 표식 읽기 1회가 늘어난 만큼만 맞췄습니다. 테스트 데이터에 표식 문서를 추가했고, 저장 테스트는 일지 문서 읽기만 세도록 바꿨습니다. 각 테스트의 원래 목적은 그대로입니다.

## 남은 Notion 의존과 주의
- 관리자·원장의 일지 조회는 기존처럼 학원 전체 행을 읽은 뒤 서버에서 쪽 나누기를 합니다(지금과 같은 비용). 날짜·학생별 서버 조회는 후속 개선 항목입니다.
- 무결성 점검(관리자가 직접 누르는 진단)은 아직 Notion 일지 DB를 읽습니다.
- 상담·문자·공통 권한·리포트 경로의 Notion 의존은 다음 점검 대상입니다.
- 실제 로그인·운영 데이터 화면, 응답 시간, 청구량은 확인하지 않았습니다.
