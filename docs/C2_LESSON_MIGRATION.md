# C2 과거 일지 이전 — 서버 진행형 dry-run·이전·대조 (전환 전)

2026-10-09. 누적 기준 `ENG-firestore-C2-auto-import.zip`. 이번 구간은 **과거 Notion 일지를 이전용 저장본으로 옮기고 대조하는 도구**만 추가합니다. 일반 일지 화면·저장/반영/삭제 경로·공개 리포트·Notion 원본·Make는 바꾸지 않았습니다. 운영 이전·전환·배포는 실행하지 않았습니다.

## 선택한 방식과 기존 방식 비교

| | 기존 화면 기반 자동 이전 (성적 등) | 이번 서버 진행형 작업 |
|---|---|---|
| 진행 주체 | 열린 브라우저가 단계 API를 반복 호출 | 서버 작업 문서(`lessonMigrationJobs/main`)가 단계·커서·잠금을 보유. 열린 관리자 화면 또는 cron이 같은 단계를 이어서 실행 |
| 창을 닫으면 | 멈춤. 다시 눌러 재개 | 진행 위치 유지. cron 설정 시 계속 진행, 아니면 화면을 다시 열면 자동 이어짐 |
| 문제 1건 | 전체 중지 | 해당 항목만 보류, 독립 항목은 계속 |
| 일시 오류 | 사용자가 재시작 | 30초부터 두 배씩(최대 30분) 대기 후 자동 재시도, 6회 실패 시 `blocked` |
| 사용자 조작 | 페이지마다 확인/재개 | 시작 1회 + 보류 항목 판단 + `보류 재확인` 1회 + 최종 전체 실행 1회 |

Notion 공식 웹훅·Make에 의존하지 않습니다. 원본은 Notion API를 `last_edited_time` 오름차순·20건 단위로 읽습니다.

### 예상 비용 (원본 5,000건 기준, 추정)
- Notion API: 조회 약 250회 + 관계가 잘린 행의 추가 조회. 기존 클라이언트 재시도(429)를 그대로 사용.
- Firestore: 행당 문서 읽기 약 6~9회 → 약 4만 회. 변경된 행만 쓰기 3회(저장본·원본 버전·이력) → 최초 약 1.5만 회. **재실행 시 변경 없는 행은 쓰기 0회**. 단계마다 작업 문서 쓰기 2~3회.
- 서버 실행: 1회 호출 기본 8초 예산(`LESSON_MIGRATION_BUDGET_MS`). 한 호출에 최소 1개 배치는 처리하므로 짧은 실행 제한에서도 진행합니다.
- cron 대기 비용: 진행 중 작업이 없으면 작업 문서 1회 읽기만 합니다.

## 구현

`api/_lib/lessonMigration.ts`
1. **scan**: 연결된 일지 DB(공유 모드는 기본 일지 DB, 개별 모드는 선생님별 DB)를 커서로 순회합니다. 행마다 기존 조회기와 같은 규칙으로 학원·과목·작성자(`sharedRecordOwner`)·학생 내부 연결을 확인하고, 필드는 기존 조회기와 같은 `sourceLessonData`로 변환합니다.
2. **catchup**: 탐색 시작 2분 전 이후 수정된 원본을 다시 대조합니다 (Notion 수정 시각이 분 단위이기 때문).
3. **app-check**: 이번 회차에 보이지 않은 저장본을 원본 페이지로 개별 확인하고(삭제·범위 이동), 진행 중이거나 결과가 미확정인 앱 반영 요청을 보류로 모읍니다.
4. **recheck**: 열린 보류를 현재 원본으로 다시 판정합니다.
5. **report**: 보류 수·유형, 이번 실행 건수, 준비 상태(`ready`)와 증거 해시를 남깁니다. `ready`는 전체 실행 + 이번 실행의 전체 원본 순회 완료 + 열린 보류 0건일 때만 true입니다.

저장 위치: `lessonSourceRecords/{실제 Notion 페이지 ID}`. 기존 Notion 행 형식(학생·과목·날짜·회차·자습 회차·작성자·공개 상태·앱 기록 ID)에 학생 내부 ID, 원본 DB ID, 연결된 앱 일지 ID, 기존 공개 리포트 문서 ID(하이픈 없는 ID 포함)를 함께 저장합니다. 가짜 Notion ID를 만들지 않고 공개 리포트 ID/reportIdentity는 읽기만 합니다. 원본 원문은 `lessonImportVersions`, 저장본 변경 전후는 `lessonMigrationHistory`에 남깁니다.

`teacherLessonDrafts`와 `lessonReports`에는 쓰지 않습니다. 그래서 전환 전에는 선생님의 초안 목록, 직전 수업, 공개 리포트가 바뀌지 않습니다. 전환 단계에서는 이 저장본을 기존 `mergeNotionRows`의 원본 행 자리에 그대로 넣는 방식입니다.

### 판단 규칙
- 학생+날짜로 묶거나 중복 제거하지 않습니다. 같은 날 두 수업은 각자 다른 원본 ID로 저장됩니다.
- 변경 없는 행(정규화한 값 해시가 같은 경우)은 다시 쓰지 않습니다. 저장본보다 오래된 원본은 덮어쓰지 않습니다.
- 앱 일지와 연결된 행(앱 기록 ID 또는 `notionPageId`)은 앱 일지를 바꾸지 않고 연결만 기록합니다. 값 차이는 정보용 건수(`appDiffers`)로만 집계합니다. 현재 화면 병합 규칙이 같기 때문입니다.
- 공통 잠금: 작업 문서 lease를 트랜잭션으로 잡아 실행자 1개만 허용합니다(화면·cron 동시 호출 포함). 행 쓰기는 lease를 다시 확인하는 트랜잭션 안에서만 합니다. 진행 위치는 배치마다 저장되므로 중단되어도 최대 1개 배치만 다시 처리하며, 다시 처리해도 결과는 같습니다.

### 보류 유형
| 코드 | 의미 | 현재대로 확정할 때 |
|---|---|---|
| STUDENT_LINK_MISSING / MULTIPLE_STUDENTS / SUBJECT_INVALID | 학생 0명·2명 이상·과목 없음 (현재 화면에도 안 보이는 행) | Notion에만 보관, 이전 제외 |
| AUTHOR_UNKNOWN | 작성 선생님 미연결·공동 | 작성자 미지정(`__unlinked_author__`)으로 이전. 누구에게도 소유권을 주지 않고 관리자·원장만 조회(현재와 같음) |
| MARKER_ORPHAN | 앱 기록 ID가 가리키는 앱 일지 없음 | Notion 작성 일지로 이전 |
| PUBLIC_REPORT_MISSING / PUBLIC_VALUES_DIFFER | 반영 완료인데 공개 리포트 없음 / 날짜·과목·출석·내용 차이 | 공개 상태는 바꾸지 않고 이전 |
| SOURCE_REMOVED | 저장본의 원본이 보관·삭제됨 | 저장본을 `removed`로 숨김 (문서 삭제 없음) |
| STUDENT_MAPPING, DUPLICATE_APP_RECORD, DUPLICATE_PUBLIC, SOURCE_IDENTITY, SOURCE_TOO_LARGE | 연결·중복·식별 충돌 | 확정 불가. 원본/연결을 고친 뒤 `수정 후 다시 확인` |
| NOTION_WRITE_UNCERTAIN, APP_WRITE_PENDING | 앱의 Notion 생성 결과 미확정·반영 진행 중 | 확정 불가. 기존 복구 경로로 해결 후 재확인 |

확정은 그때 본 원본 버전에만 적용됩니다. 원본이 다시 바뀌면 새로 보류됩니다. 결정자·시각은 보류 문서의 `decisions`에 남습니다.

## 실행 경로
- 관리자(main 학원) → 설정 탭 → `과거 Notion 일지 이전 · 관리자`. 펼치기 전에는 아무것도 읽지 않습니다.
  - `점검만 실행 (저장 없음)`: 분류·보류 목록만 만듭니다(저장본 쓰기 없음).
  - `전체 이전 시작·재개`: 진행 중이던 작업은 저장된 위치에서 이어집니다.
  - `보류 재확인`, `일시 중지`. 다른 모드가 진행 중이면 새로 시작하지 않습니다(`LESSON_MIGRATION_RUNNING`).
- API (workspace, 관리자만): `GET lesson-migration-status`, `POST lesson-migration-start|step|pause|hold`.
- 예약 실행: `vercel.json`에 `/api/cron/lesson-migration`을 기존 workspace 함수로 연결했습니다(함수 수 증가 없음). 기본 일정은 **매일 1회**(모든 Vercel 요금제에서 배포 가능). Pro 요금제면 `*/5 * * * *` 등으로 바꾸면 창을 닫아도 계속 진행합니다. `CRON_SECRET`(16자 이상)이 없으면 cron 요청은 401로 거부되고, 화면 실행만 동작합니다.

## 미실행·미확인
- 운영 Notion/Firestore 대상 실행, 실제 원본 건수·보류 분포, 실제 화면·응답 시간·청구량은 확인하지 않았습니다.
- 운영 함수 최대 실행 시간 미확인 → 기본 예산 8초. 실행 제한으로 중간에 끊겨도 같은 배치를 다시 처리할 뿐 결과는 같습니다.
- Vercel 요금제 미확인 → cron은 매일 1회로 두었습니다.
- 공개 리포트 비교는 날짜·과목·출석·내용 포함 여부만 봅니다. Make가 만든 피드백 형식이 다르면 `PUBLIC_VALUES_DIFFER`가 많이 나올 수 있으니 점검 실행 결과로 먼저 확인하세요.
