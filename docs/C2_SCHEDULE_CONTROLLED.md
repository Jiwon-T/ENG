# 일정의 조건부 Firestore 전환

## 구현
- 앱 일정의 초안 저장과 학생·학부모 공개/취소 분리. 공개 대상 전체를 한 트랜잭션으로 적용합니다.
- 대상 학생을 빼면 원래 시간의 취소 복사본을 유지하고 기존 공개 ID를 재사용합니다. 신규 앱 일정은 appScheduleId로 구분하며 실제 Notion ID를 만들어낸 것처럼 저장하지 않습니다.
- 공개/삭제 이력 보존, 중복 공개 방지, stale revision/학생 연결/소유자/학원 검증. 공개 실패 시 일부 학생만 반영되지 않습니다.
- 앱 소유 일정에 대한 늦은 기존 투영은 적용하지 않으며, 관리 일정과 공개 복사본이 ‘오늘 수업’에 중복 표시되지 않습니다.

## 기존 조회를 유지하는 전환 조건
배포만으로 전환하지 않습니다. appScheduleAuthority와 실제 scheduleVerificationRuns 검증 기록이 일치해야 앱 경로를 사용합니다. 조건이 없으면 기존 저장/반영/원본 조회와 장소 옵션을 유지합니다.

관리자(main 학원) 시간표·일정 탭의 접힌 ‘일정 앱 전환’:
1. 대조 (저장 없음): core/class 전환 상태, 장소 옵션, 전체 Notion 일정과 기존 앱 일정 필드, 학생 내부 연결, 진행 중 요청, 원본에서 사라진 기록을 확인.
2. 원본·장소 준비: 현재 기존 source reader가 허용한 원본을 앱 기록으로 가져옵니다. 기존 앱 기록을 덮어쓰지 않으며 중단 후 재실행하면 이미 저장한 원본을 보존합니다.
3. 원본 편집을 중단하고 다시 대조. 준비되지 않은 연결/장소/필드/삭제/부분 요청은 전환 거부.
4. 대조 후 앱 전환: 최신 원본을 다시 확인하고 DB revision/hash를 트랜잭션에서 검증한 뒤 전환 표식과 증거 기록을 생성합니다. 캐시를 비워 이전 원본 snapshot을 재사용하지 않습니다.

원본 전체 대조는 최대200건, 앱 준비는 source reader 최대200건, 저장 기록 대조는 최대500건입니다. 초과하면 잘라 전환하지 않고 중단합니다. 원본 관계가 잘린 경우와 삭제/중복/필드 불일치는 별도 검토 항목으로 남기며 임의 삭제/병합하지 않습니다. 상세 원본 수와 실제 대조 결과는 운영에서 미확인입니다.

## 자동 검토에 따른 변경
기존 원본 조회를 무조건 빈 결과로 바꾸는 초기 변경은 자동 승인 검토가 미이전 일정 누락/서비스 중단 위험으로 거부했습니다. 해당 변경은 실행하지 않았고, 실제 검증 증거가 없는 한 기존 경로를 유지하는 조건부 전환으로 구현했습니다. 운영 표식을 수동으로 만들어 우회하지 않습니다.

## 검증
lint 통과, 전체 테스트663/663 통과, build 통과, Native Node workspace import 통과.
모의 검증: 초안 비공개, 공개 원자성/실패 rollback, 중복 공개/옛 revision 거부, 대상 제외의 원래 시간·ID 유지, 취소와 이력, 권한/학원, 검증 없는 표식 거부, 미이전 원본/옵션이 있으면 활성화0쓰기, 정상 대조의 증거 기록, 오늘 수업 중복 제거. 기존 Notion 취소/재시도 경로도 회귀 통과.
실제 운영 이전/활성화/Notion 변경/배포/문자/Make 변경은 실행하지 않았습니다. 실제 화면·요청 수·속도·Firestore 청구 단위는 미확인입니다. 기존 CSS import와 큰 bundle 경고는 남습니다.

## 바뀐 파일 / 안 바꾼 것
appSchedule/scheduleReadiness, 보호된 workspace 분기, 관리자 ScheduleTransitionPanel, 공개 복사본의 appScheduleId 처리/오늘 수업 중복 제거, 오류 안내, 테스트. appAcademic의 검증 함수를 일정에서도 재사용할 수 있게 export만 추가했습니다.
성적 기능·학부모/학생 공개 화면·일지 입력 폼·계정/PIN/리포트 주소·기존 데이터/운영 설정은 변경하지 않았습니다. 서버 변경 이력은 보존하며 학생 개인정보를 브라우저 저장소·콘솔에 추가하지 않았습니다.

전체 앱의 Notion 독립 운영 완료는 아닙니다. 전환 전에는 기존 경로가 유지되고, 준비/대조는 명시적으로 누를 때만 Notion을 조회합니다. 원본 추가/삭제가 검증 중 일어나지 않도록 실제 운영에서 편집 중단 시점과 최종 대조를 확인해야 합니다.
