# 일정 장소 옵션 동기화 구간

체크포인트 9 및 핫픽스 1~7 전체를 포함합니다. 이번 요청의 1번만 구현했습니다.

## 원인과 실제 구조

2026-10-06(한국 시간) 읽기 전용으로 DB_일정표를 확인했습니다. DB ID는 3430f1a4-9dde-4b4c-a5cf-0d11b913b38c, 데이터 소스는 5d8cebd0-a667-4c73-bd4b-d480b2cf87e2입니다. 장소는 select이며 실제 순서대로 학원·이충·용죽·고덕·온라인·기타입니다. 기존 앱 화면과 서버 입력 스키마는 학원·온라인·기타 세 가지만 고정 허용해 이충/용죽/고덕 일정을 수정할 수 없었습니다. 노션 DB 수정은 필요하지 않습니다.

## 변경

- 인증된 schedule-options 조회가 일정표의 장소 select 옵션을 읽습니다. 편집창을 열거나 장소 목록 새로고침을 누르면 현재 옵션을 가져옵니다. 옵션 이름·순서는 노션을 따르며 향후 옵션 추가에도 코드 변경이 필요하지 않습니다.
- 서버 입력 스키마의 고정 장소 enum을 제거하고 저장 및 반영 직전에 현재 노션 옵션으로 검증합니다. 현재 옵션에 없는 값은 쓰기 전에 장소별 안내 메시지로 거절하여 잘못된 옵션을 자동 생성하지 않습니다.
- 기존 일정의 장소는 그대로 조회합니다. 비어 있던 장소를 학원으로 바꾸지 않습니다. 미지정 선택은 Notion select:null로 저장됩니다. 삭제된 기존 옵션은 화면에 현재 옵션에 없음으로 남겨 표시하며 새 옵션을 선택하도록 안내합니다. 목록 조회 실패 시 고정 옵션으로 대체하지 않고 오류와 목록 새로고침을 제공합니다.
- 기존 원본 페이지 ID, 리비전 충돌 검증, 소유자·담당 학생 권한, 여러 대상 학생 및 기존 중복 생성 방지·응답 유실 복구를 유지합니다. 쓰기가 이미 시도된 불변 요청의 복구는 장소 옵션 변경 때문에 막지 않고 기존 쓰기 기록으로 실제 결과를 확인합니다. 새로운 쓰기는 현재 옵션을 검증합니다.

## 검증과 범위

테스트 410개 통과. TypeScript 검사, Vite 빌드, 서버 네이티브 import 검사 통과. 기존 빌드의 큰 chunk 및 firebase 혼합 import 경고는 유지됩니다.

새 검증은 노션 옵션 조회·추가·삭제 반영, 누락/잘못된 select 스키마, 장소별 저장·수정, 소유권·리비전 충돌, 기존 Notion 일정의 이충 및 빈 장소 조회, 용죽에서 고덕으로 동일 페이지 수정, 반영 전 옵션 제거 거절, 빈 장소의 null 반영, 옵션 변경 후 응답 유실 복구를 포함합니다. 앱 저장·반영 검증은 가짜 Notion/Firestore를 사용했습니다. 실제 노션은 스키마만 조회했으며 운영 일정 작성·수정, 배포, Make 변경은 수행하지 않았습니다.
