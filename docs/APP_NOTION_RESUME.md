# 앱–노션 전환 재개 기록: 체크포인트 8

체크포인트 7 전체 코드에 누적 적용했다. 이전 기능·학생/리포트 ID·파스텔 핑크 UI를 유지한다. 이전 기록은 APP_NOTION_CHECKPOINT_7.md에 보관했다.

## 완료 범위

- 학생관리 카드 → 보호자 문자: 과목, DB_메시지 템플릿, 앱에서 반영 완료한 수업일지를 선택한다. 템플릿 없이 발송은 지원하지 않는다. 기존 개인 노션 일지는 이번 선택 목록에 포함하지 않는다.
- 실제 노션 템플릿 DB와 학생 DB 속성을 읽기 전용으로 확인했다. 템플릿은 서버에서 현재 노션 값을 조회한다. 단체 유형도 선택한 학생 한 명 대상으로만 생성하며 단체 일괄 발송은 하지 않는다.
- 학생 호칭/학생호칭, 보호자이름, 학교, 학년, 수강료, 납부기한, 출결, 태도, 숙제, 테스트, 단어·단어테스트 점수, 내신 대비 점수, 내용 및 피드백, 피드백, 문항, 오답, 틀린단어, 수업일, 과목, 수업·자습 시작/종료를 치환한다. 틀린단어는 단어 테스트의 오답 수를 뜻하며 개별 단어 목록은 저장되어 있지 않다. 점수는 정답/문항의 백분율로 반올림하며 실제 0을 보존한다.
- 템플릿의 <br>와 이스케이프된 중괄호를 정규화한다. 값이 없는 변수는 {{변수}}로 남겨 사용자가 입력하거나 해당 항목을 지우게 한다. 미치환 변수가 있는 문자 저장·발송은 막는다. 생성 본문은 사용자가 수정할 수 있다.
- 본문 저장은 teacherMessages에 불변 요청을 먼저 기록한 뒤, 기존 학생 페이지의 메시지템플릿선택·완성된 문자본문만 PATCH한다. 노션 저장 실패 시 같은 ID·본문으로 재시도한다. 이 저장은 문자를 보내지 않는다. 과거 실패한 저장도 이력에서 재시도할 수 있다.
- 별도 발송 버튼을 누르기 전에 저장한 수신자·본문을 표시하고 확인 체크를 요구한다. 수업일지 반영과 문자 발송은 독립적이다. 보호자 번호가 바뀌면 기존 요청을 발송하지 않는다. 진행 중인 보호자 연락처 변경도 차단한다.
- 기존 workspace API를 확장했다. 새 Vercel 함수는 추가하지 않았다. 관리자·원장은 같은 학원 학생, 일반 교사는 현재 담당 학생·과목만 조회·작성한다. 발송은 요청을 준비한 계정만 할 수 있다. 다른 학원 자료·다른 학생의 일지·다른 DB의 템플릿은 거절한다.
- teacherMessages·teacherMessageSendLocks는 서버 전용이며 Firestore 규칙에서 클라이언트 직접 접근을 차단한다. 본문과 수신자는 발송 이력에 저장된다.

## Bati 연결 설정과 결과 의미

서버 전용 환경변수 2개를 .env.example와 환경변수 검사 목록에 추가했다.

1. BATI_WEBHOOK_URL: 기존 https://app.bati.ai/webhook/... 주소를 서버에 설정한다. 비밀 주소는 코드·ZIP·브라우저에 넣지 않는다.
2. BATI_MESSAGE_PARAM: 기존 Bati 웹훅이 실제 문자본문으로 받는 정확한 query 매개변수 이름을 설정한다. 보호자 번호 매개변수는 기존 구조의 보호자연락처를 사용한다. 본문 매개변수는 추측하지 않았다. 기존 노션 발송 수식 조회가 시간 초과되어 정확한 계약을 확인하지 못했다. 배포 전에 기존 수식 또는 Bati 웹훅 설정과 대조해야 한다. 이름을 확인하기 전 발송을 활성화하지 않는다.

현재 어댑터는 기존 웹훅 형태의 GET + URLSearchParams를 사용한다. HTTPS app.bati.ai의 webhook 경로만 허용하고 리디렉션을 따르지 않는다. 본문·전화번호는 이 서버 호출의 URL에 들어가므로 Bati 측 로그에도 기록될 수 있다. 실제 Bati 계정으로 호출하거나 전송 결과를 검증하지 않았다.

- 발송 전 거래에서 요청을 sending으로 저장하고 수신자+본문 해시 잠금을 만든다. 같은 요청 재호출·동시 클릭·새 ID로 동일 본문을 다시 요청해도 네트워크 전송은 한 번만 한다.
- HTTP 2xx는 ‘발송 요청 접수’이며 수신자에게 도착했다는 뜻이 아니다. 실제 전달 성공 여부는 Bati 발송 내역에서 확인해야 한다.
- 네트워크 오류·타임아웃·리디렉션·비2xx는 uncertain으로 잠근다. 외부 호출 후 Firestore 저장이 실패하면 sending 상태로 남아 재전송을 차단한다. 응답 유실 시 자동 재시도하지 않는다.
- 이력의 결과 확인은 서버에 저장된 상태를 읽는다. Bati 영수증 조회·수동 잠금 해제 기능은 구현하지 않았다. uncertain/sending 또는 동일 본문을 의도적으로 재발송해야 하는 경우 Bati 기록을 확인한 후 별도 운영 절차가 필요하다. 자동 해제는 하지 않는다.
- 발송 직전 학생 원본과 소속 및 연락처 변경 잠금을 다시 확인한다. Notion 조회와 외부 발송은 원자 거래가 아니므로 그 사이 Notion에서 직접 번호를 수정하는 경쟁을 완전히 제거할 수는 없다.
- 학생 페이지의 문자본문은 마지막 준비된 문자의 백업이다. 발송은 해당 페이지의 현재 본문 대신 앱에 저장한 확인 대상 본문을 사용한다. 노션 문자 저장과 노션 수동 편집의 동시 경쟁을 조건부 PATCH로 막을 수는 없다.

## 검증 및 사용자 확인

전체 테스트 328개, TypeScript 검사, 프로덕션 빌드 검증. 기존 큰 번들 경고는 남아 있다. 신규 검증은 변수·0점, 권한·원본, 연락처 변경, 미완료 연락처 수정, 노션 저장 실패 복구, 동시 발송·동일 본문 중복, 응답 유실·타임아웃·HTTP 실패·리디렉션, 발송 전/후 거래 실패와 구성 검사를 모의 Firestore/Notion/HTTP로 확인한다.
