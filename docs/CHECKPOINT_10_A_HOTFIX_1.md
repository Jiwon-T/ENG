# 체크포인트 10 A hotfix 1 — 상담·신입생, 일지 조회, 일정 모달

2026-10-06. 누적 기준은 ENG-app-notion-checkpoint-10-A.zip입니다. 이전 단어장 디자인과 A 구간 변경을 모두 포함합니다. Bati(B)는 아직 진행하지 않았습니다.

## 상담·신입생 관리

- 상단 영역을 상담·신입생 관리로 바꾸고 전체/상담만 진행/등록 첫 달/추가 과목 상담으로 나눴습니다. 서버에서 구분을 적용한 뒤 8개씩 페이지네이션하므로 다른 페이지의 학생도 정확히 분류합니다.
- 새 원서는 상담만 진행으로 시작합니다. 상담만 저장하면 원서 초안만 보관하며 Notion 학생·수강과 앱 명부를 생성하지 않습니다. 등록이 결정되면 같은 원서를 열어 진행 상태를 등록 첫 달로 바꾸고 저장한 뒤 기존 노션 반영을 실행합니다.
- 등록 첫 달의 신입생은 기존 안전한 등록 경로로 학생·수강·계정/리포트 연결을 만들며, 노션 반영이 완료된 경우에만 재원생으로 전환할 수 있습니다. 다음 달이면 전환 안내를 표시합니다. 자동 월간 작업은 추가하지 않았고 전환 버튼을 직접 사용합니다.
- 재원생으로 전환하면 상단 상담·신입생 목록의 모든 구분과 건수에서 빠집니다. 아래 학생 관리의 기존 카드에서 계속 관리합니다. 새 학생 카드/새 Notion 학생을 복제하지 않습니다. 원서 기록은 삭제하지 않고 Firestore에 전환 시각·처리자를 보존합니다. 기존 학생·수강 ID, 앱 연결, 리포트 URL/PIN은 변경하지 않습니다.
- 기존 학생 추가 과목 상담에서는 학생을 선택해 기존 학생 ID에 상담을 연결합니다. 이 원서로 신규 학생·수강을 생성할 수 없도록 서버에서도 막았습니다. 목록의 기존 학생 수강 관리 버튼으로 기존 과목별 편집 화면을 열어 실제 추가 등록합니다. 공동 담당·다른 과목·기존 반 보존은 원래 수강 편집 경로를 사용합니다.
- 추가 과목의 실제 등록 상태와 미완료 수강 변경 여부를 확인한 뒤 수강 완료·목록에서 정리 버튼으로 상담 목록에서 제외합니다. 과목이 대기/중단이거나 아직 변경 중이면 정리를 거부합니다. 상담 원서 내용이 기존 학생의 연락처/개인 정보를 덮어쓰지는 않습니다.
- 위 구분과 전환 상태는 앱 내부 메타데이터입니다. Notion 속성 추가/운영 데이터 이관은 하지 않았습니다. 구분 필드가 없는 과거 원서는 기존 등록 원서 동작으로 유지합니다. 기존 상담·입학 원서 전체 항목은 유지했습니다.

## 일지 조회

수업 일지 작성 바로 오른쪽으로 일지 조회 탭을 옮겼습니다. 행 전체 클릭 또는 키보드로 날짜 버튼을 선택하면 상세 모달이 열립니다. 목록 행의 수정·삭제 버튼은 제거하고 상세 모달로 옮겼습니다. 수정은 기존 일지 편집 모달로 이어지고 삭제는 최종 확인 후 같은 원본을 보존하는 삭제 경로를 사용합니다. 관리자 또는 작성한 선생님만 조작 버튼을 사용할 수 있고 원장의 타인 일지는 조회 권한만 유지합니다. 충돌 비교도 상세 모달 안에서 제공합니다. 일지 변경 후 목록은 기존 필터를 유지하며 다시 읽습니다. 엑셀 내보내기와 서버 권한은 유지합니다.

## 일정·정규 시간표

일정 반영은 현재 입력을 고정해 저장 → 같은 ID로 반영 순서로 처리합니다. 이미 동일하게 저장한 입력이면 중복 저장을 하지 않습니다. 별도 저장 버튼은 초안 저장 용도로 유지합니다. Notion 저장 대기/충돌이 있는 기존 요청은 새로운 입력으로 덮지 않고 기존 결과 확인·재시도와 충돌 복구를 사용합니다.

반영을 누른 뒤 모달 닫기와 Esc를 바로 사용할 수 있습니다. 모달 종료가 진행 중인 저장/반영 요청을 취소하지 않습니다. 결과/오류는 모달 밖 상단 안내에 표시하고 목록을 갱신합니다. 저장 실패·응답 유실은 자동 재요청하지 않고 같은 원본 확인을 사용합니다. 이 동작은 현재 앱 화면을 유지한 채 모달을 닫는 경우이며 브라우저 탭 전체 종료까지 서버 실행을 보장하는 새로운 작업 큐는 도입하지 않았습니다.

정규 시간표는 원래 반 저장이 Notion 반영까지 실행하고 있어 버튼을 저장·반영으로 명확히 했습니다. 처리 중에도 모달을 닫을 수 있고, 전송 전 미저장 변경을 닫으면 확인합니다. 기존 반/시간표/교재 ID 보존과 수정 시각 충돌 검증을 유지했습니다.

## 배포 후 사용자 확인

1. 원장/관리자로 신규 상담만 저장: 상담만 진행에 남고 실제 학생/수강이 생성되지 않는지 확인합니다. 같은 원서를 등록 첫 달로 저장·노션 반영해 첫 달 목록과 학생 연결을 확인합니다.
2. 재원생으로 전환: 상단 전체/등록 첫 달 목록과 건수에서 빠지고, 아래 학생 관리 카드와 기존 리포트 URL/PIN이 유지되는지 확인합니다. 새로고침해도 전환한 원서가 돌아오면 안 됩니다.
3. 기존 학생을 선택해 추가 과목 상담 저장: 학생 중복 없이 추가 과목 상담에 표시되는지 확인합니다. 기존 학생 수강 관리에서 상담 과목을 등록한 후 목록에서 정리합니다. 다른 과목/공동 담당/기존 이력이 유지되는지 확인합니다.
4. 일지 조회 행 클릭과 키보드 날짜 선택으로 상세 모달을 엽니다. 본인/관리자 수정·삭제와 타인 일지의 조회 전용 동작을 확인합니다. 수정 후 목록에서 새 내용이 표시되는지도 확인합니다.
5. 신규/수정 일정에서 별도 저장 없이 반영을 누른 뒤 즉시 닫습니다. 상단 결과와 달력, 학생·학부모 리포트, 같은 Notion 원본을 확인합니다. 정규 시간표도 저장·반영 후 바로 닫고 결과를 확인합니다.

운영 데이터 변경, 실제 문자 발송, 배포와 Make 중단은 하지 않았습니다. 다음 구간은 사용자가 재개를 요청하면 B입니다.
