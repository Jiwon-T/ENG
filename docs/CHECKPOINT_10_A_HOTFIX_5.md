# 체크포인트 10 A hotfix 5 — Firestore 자원 제한 대응·사용량 감소

2026-10-06. hotfix 4까지 전체 누적 변경을 포함합니다. B는 보류 중입니다.

## 확정된 운영 원인

오류 ID cd67247d-1c97-47ea-85ed-08be17b77df9의 운영 로그:

- GET /api/teacher/workspace, HTTP 500
- error WORKSPACE_ERROR
- failureStage workspace-account
- causeCode FIRESTORE_GRPC_8

동시에 다른 계정 조회 요청에서도 같은 코드가 기록됐습니다. Firestore gRPC 코드 8은 RESOURCE_EXHAUSTED입니다. 즉 사용자/작업 계정 문서를 읽을 때 Firestore가 사용량·자원 제한으로 거절했습니다. 이 로그는 초기화 오류와 구별됩니다. 어떤 구체적 일일/속도/자원 한도가 초과됐는지는 기존 숫자 코드만으로 확정할 수 없습니다.

사용자가 확인한 총 사용량은 단위 읽기 31만, 단위 작성 14만, 실시간 읽기 단위 670입니다. 집계 날짜 범위와 해당 DB의 결제/무료 할당 적용은 확인되지 않았습니다. 따라서 이 수치를 당일 사용량으로 가정하거나 반드시 무료 일일 한도 소진이라고 확정하지 않습니다. Authentication 사용자 9명과 SMS 한도는 이 Firestore 읽기 실패와 별개입니다.

## 수정

1. Firestore 자원 제한을 별도 FIRESTORE_RESOURCE_EXHAUSTED/HTTP 429로 안내합니다. Retry-After 30초를 포함하고 서버 로그의 원인 코드를 유지합니다. 일반 연결 실패 문구로 감추지 않습니다.
2. 동일 계정이 자원 제한 응답을 받으면 클라이언트의 추가 선생님 API 요청을 30초간 일시 중지합니다. 자동 재시도나 자동 재발송/저장을 하지 않습니다. 계정이 바뀌면 이전 계정의 일시 중지가 적용되지 않습니다. 30초는 재시도 폭주를 줄이는 간격이며 한도 복구 시간의 약속이 아닙니다.
3. 동시 요청의 사용자/작업 계정 문서 읽기와 동일 담당 학생 소속 묶음 읽기를 공유합니다. 완료된 권한 정보는 캐시하지 않아 다음 요청에서 비활성/소속 변경을 다시 확인합니다. 다른 DB/사용자 키의 조회는 공유하지 않습니다.
4. Notion 원본 JSON은 기본적으로 서버 메모리의 비공개 읽기 캐시만 사용합니다. 원본 페이지 전체를 Firestore teacherNotionMirrors에 반복 저장·조회하던 기본 경로를 사용하지 않습니다. 큰 JSON은 읽기/쓰기 단위 사용량을 증가시킬 수 있어 이를 줄였습니다. 캐시는 기존 사용자·역할·학원·담당·조회 조건으로 격리하고 60초 만료/새로고침/서버 변경 무효화를 사용합니다.
5. 실제 일지·성적·일정 리포트, 학생·수강 연결, 저장 요청/복구 journal과 계정 권한은 기존 Firestore에 계속 저장합니다. 학생/Notion/리포트 ID는 변경하지 않습니다. 기존 원본 JSON 캐시 문서를 삭제하지 않았습니다. 기존 지속 캐시 구현은 명시적인 내부 호출용으로 보존하고 그 회귀 테스트도 유지합니다.

캐시 재사용으로 이미 소진된 외부 할당량을 되돌릴 수는 없습니다. 요청 폭주와 앞으로 발생할 불필요한 읽기/쓰기를 줄이는 수정입니다. 권한 확인을 생략하거나 다른 데이터베이스로 우회하여 접근을 허용하지 않습니다.

## 검증

전체 회귀 테스트 471개, 타입 검사, native Node 서버 import, 프로덕션 빌드 통과. 기존 큰 번들/Firebase mixed import 경고는 남아 있습니다.

추가 5개 테스트: 동시 권한 읽기 공유 및 다음 요청 재확인/실패 재확인, 실물 teacherActor 경로에서 3개 동시 요청의 두 문서 읽기 공유와 후속 비활성 차단, 오류 429 안내와 원시 정보 미노출, 계정별 30초 요청 중지·저장 자동 재시도 없음, 원본 JSON 읽기 캐시의 Firestore 읽기/쓰기 0회·사용자 분리·새로고침/무효화.

기존 담당 범위 동시 조회 테스트의 묶음 읽기 기대값을 2회에서 1회로 갱신했습니다. 다음 요청에서 변경된 소속/교사 상태를 거부하는 테스트는 유지했습니다. SDK 초기화 및 Notion DB 조회 hotfix도 그대로 포함됩니다.

## 운영 확인과 복구

1. Firebase 콘솔에서 현재 운영의 이름 있는 Firestore DB를 선택하고 사용량의 날짜 범위를 오늘로 확인합니다. 읽기/쓰기 단위와 한도 또는 자원 제한 경고, 프로젝트 결제 활성 상태를 확인합니다. 총/누적 수치를 당일 한도로 판단하지 않습니다.
2. Google Cloud의 Firestore API 할당량/시스템 제한 화면에서 실제로 초과된 항목을 확인합니다. 오류가 일일 무료 할당량이면 일일 초기화를 기다리거나 사용자가 결제 설정을 검토해야 합니다. 처리량/속도 제한이면 해당 제한을 확인하고 낮은 요청량에서 재확인합니다.
3. 이 누적 ZIP은 불필요한 Firestore 원본 캐시 사용과 중복 요청을 줄이는 코드입니다. 배포만으로 이미 걸린 한도가 즉시 해제된다고 보고하지 않습니다. 할당량이 허용되는 상태가 된 뒤 선생님방과 학생 리포트를 다시 확인해야 합니다.
4. 재배포 후 자원 제한이 남으면 새 오류 ID와 오늘 범위의 한도 항목을 알려 주세요. 한도를 추측하여 다른 DB로 연결하거나 반복 새로고침하지 않습니다.

Firestore Enterprise의 공식 무료 할당량은 하루 읽기 50,000단위/쓰기 40,000단위이고 태평양 자정 무렵 초기화됩니다. 단위 읽기/작성은 문서 개수와 다르게 데이터 크기를 반영합니다. 이 프로젝트/DB에 그 무료 할당량이 적용되는지는 콘솔에서 확인해야 합니다.
