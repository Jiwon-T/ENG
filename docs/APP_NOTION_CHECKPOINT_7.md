# 앱–노션 전환 재개 기록: 체크포인트 7

기준: 체크포인트 6 전체 코드에 누적 적용했다. 기존 1~6단계, 수업 내용 필수, 특이사항 연동, 반영 중 수업일지 팝업 닫기 수정은 유지했다. 이전 기록은 APP_NOTION_CHECKPOINT_6.md에 보관했다.

## 완료 범위

- 앱의 수업일지·성적·일정 반영 경로가 Make 웹훅을 호출하지 않는다. 일정의 Notion 반영 요청 수식에서 Make 주소를 추출해 실행하던 코드를 제거했다. 기존 Make 시나리오와 Notion 수식은 수정하거나 중단하지 않았다.
- 일정 반영: 앱 초안 → 기존 중앙 일정 DB 저장 → 선택된 모든 학생의 studentSchedules 직접 반영 → 중앙 반영 완료 표시 → 앱 반영 완료. 새 Vercel 함수나 비밀 환경변수는 추가하지 않았다.
- 여러 학생을 선택하면 전원 반영한다. 대상에서 일부 제외하면 기존 개인 일정만 취소 처리한다. 삭제는 중앙 일정을 취소로 저장하고 모든 개인 반영을 확인한 뒤 관리자 목록에서 숨긴다. 물리 삭제 대신 취소 기록을 남긴다.
- 반영은 기존 학생 식별 연결을 읽고, 한 학생이라도 매핑/학원 소속이 잘못되면 개인 일정 기록은 변경하지 않는다. 현재 대상·제외 대상·동기화 버전 상태를 Firestore 거래 한 번으로 저장한다. 완료 시간과 기존 공개 일정 ID를 유지하고, 재포함하면 같은 개인 일정 ID를 재사용한다.
- 일정 종류(기타/보강/휴강 등)를 그대로 전달한다. 중앙의 변경 상태는 기존 공개 DTO 호환을 위해 학생·학부모 화면에서 예정으로 정규화한다. 중앙 Notion에는 변경을 그대로 저장한다.
- scheduleSyncStates는 원본 일정 ID를 정규화한 해시별 소유 초안 ID·앱 revision·원본 시각을 저장한다. 서버 전용이며 Firestore 직접 읽기·쓰기를 차단했다. 선택 100명 한도와 거래 쓰기 한도를 검증한다. 누적 제외 대상이 지나치게 많아 안전한 동시 쓰기 범위를 벗어나면 전체 거래를 중단하며, 부분 반영하지 않는다.
- 기존 Make 일정 웹훅은 같은 직접 반영 함수를 사용한다. 앱 소유 일정은 날짜가 없거나 이전 날짜이거나 더 미래 날짜여도 Make 본문으로 덮어쓰지 않는다. 아직 앱으로 전환하지 않은 일정은 실제 sourceUpdatedAt 순서를 비교한다. 빈 학생 목록을 통한 전체 취소 이후 오래된 전송이 학생을 복원하지 않는다.
- 원본 ID의 하이픈 유무를 정규화하고 이전 compact/dashed 중복 개인 일정은 기존 공개 ID 하나를 유지하면서 정리한다.

## 노션 저장의 공통 복구

- teacherNotionWrite는 수업일지·성적·일정에 공통으로 사용한다. 기존 초안 문서 안에 revision·불변 속성·원본 DB·예상 편집 시각·기존/발견한 페이지 ID·원격 요청 시도·확인 완료·3분 lease를 저장한다.
- 새 페이지 생성 전에 앱 기록 ID로 기존 행을 조회한다. 타임아웃/5xx/응답 유실 후 생성 결과를 확인하지 못하면 자동으로 같은 페이지를 또 생성하지 않는다. 같은 앱 기록 ID의 중복 페이지는 거절한다.
- 응답이 유실됐지만 노션 값이 저장한 입력과 일치하면 기존 페이지를 확인해 복구하며 CREATE/PATCH를 반복하지 않는다. 확정 4xx 거절은 재시도할 수 있다. 결과가 불명확하고 실제 값이 일치하지 않으면 NOTION_WRITE_RESULT_UNCERTAIN으로 잠근다. 이 경우 원격 상태를 확인해야 한다.
- 저장 직전과 저장 후에 원본 DB·페이지 보관 상태·편집 시각·필드 값을 확인한다. 관계 순서, 텍스트 분할, 동일한 시간의 타임존 표기 차이는 같은 값으로 비교한다. 잘린 관계는 일치로 인정하지 않는다.
- 노션 저장을 확인한 뒤 리포트 반영이 실패하면 같은 revision으로 복구한다. 저장한 대상 값이 나중에 수동 변경됐다면 충돌을 안내하고 자동 덮어쓰기를 하지 않는다. 관련 없는 수동 메모는 보존한다.
- 노션 반영/리포트 확인이 끝나지 않은 초안은 새 입력으로 저장하거나 일반 삭제로 덮어쓸 수 없다. 먼저 기존 요청을 완료한다. 실패한 일정 삭제도 새 revision을 추가하지 않고 원래 취소 revision으로 재시도한다.
- 실행이 중단되어 publishing/notion_saved 단계에 남은 기록은 3분이 지나고 원격 lease가 끝나면 다시 반영할 수 있다. 화면을 새로고침한 뒤 저장 결과 확인·재시도 버튼을 사용한다. 살아 있는 실행이 진행 중일 때는 재시도를 차단한다.
- Notion은 조건부 원자 PATCH를 제공하지 않는다. 최종 조회와 PATCH 사이 외부 편집 경쟁을 완전히 없앨 수는 없다. 원격 상태와 앱 거래는 분산 거래가 아니므로 자동 롤백하지 않고 저장한 요청으로 복구한다.

## 수업일지와 성적

- 수업일지는 기존 앱 직접 리포트 우선 반영을 유지한다. 노션 복사가 실패하면 학생·학부모 리포트는 유지하며 노션 대기로 표시하고 같은 요청을 재시도한다. 기존 reportIdentity·학생 연결·과제·공개 범위는 보존한다.
- Make 대응용 영어 전용 제한을 제거했다. 설정한 과목별 수업일지 DB와 과목 속성을 사용하며 실제 수학 수업일지 저장 경로를 모의 HTTP로 확인했다.
- 수업일지 Make 웹훅은 canonical/compact 양쪽의 앱 관리 마커를 거래 안에서 확인한다. 앱 일지는 Make 날짜와 관계없이 덮어쓰지 않는다. 미전환 일지는 sourceUpdatedAt 순서를 비교하며 compact 원본을 정규화한다.
- 과거 점수 보충(backfill)도 앱 직접 일지에 예전 점수를 다시 채우지 않도록 앱 관리 마커를 확인한다. 직접 반영의 낮은 revision이 더 높은 앱 revision을 덮어쓰지 못한다.
- 성적은 기존 Notion 실제 값 조회 → syncAcademicPage 직접 반영을 유지한다. 노션 저장 후 앱 성적 반영이 실패해도 같은 노션 행으로 재시도한다. 실제 0점과 미제출 처리 및 수동 수정의 편집 시각 검사를 유지했다. 기존 syncAcademicPage의 원본 버전 보호는 그대로 사용한다.
- 가져온 기존 성적을 저장할 때 조회한 Notion 편집 시각도 보관한다. 노션 생성 결과를 모르는 상황에서 새 성적 행을 중복 생성하지 않는다.
- 단일 수업일지·반별 수업일지·성적·일정 화면에 저장 결과 확인·재시도를 제공한다. 이 버튼은 저장한 입력을 사용하며, 나중에 화면에서 바꾼 값은 해당 재시도에 포함하지 않는다.

## 검증

전체 테스트 **315개 통과**, TypeScript 검사 및 프로덕션 빌드 통과. 기존 큰 번들 경고는 남아 있으나 빌드 실패는 아니다.

새 테스트는 다중 학생 일정, 대상 일부 제외·재포함·전체 취소, 공개 ID·완료 시간 보존, 학원 소속 오류, 거래 실패의 원자성, 늦은 Make/날짜 없는 Make/미래 날짜 Make 차단, 오래된 앱 revision, 노션 생성·수정 응답 유실, 중복 앱 기록 ID, 원본·편집 충돌, 불변 요청 위조, lease 만료 후 복구, 성적 0점과 앱 반영 실패 재시도, 실제 수학 수업일지 생성 경로를 확인한다. 전체 일정 저장→직접 개인 반영→대상 제외→삭제의 실제 함수 경로를 모의 HTTP와 거래형 Firestore로 검증했다.

운영 데이터 변경·배포·실계정 클릭·문자 발송·Make 시나리오 중단은 하지 않았다. 노션 반영 요청 링크 없이도 앱 일정 반영이 완료되는지, 실제 두 학생 일정에서 한 명 제외와 삭제 취소, 수업일지와 성적의 학생·학부모 공개 화면을 사용자 배포 후 확인한다. 기존 노션 수식/개인 노션 DB와 운영 Make 시나리오는 백업으로 남아 있다.

## 범위와 남은 작업

- 이번 개인 일정 직접 반영은 앱의 학생·학부모 리포트 저장소 대상이다. 기존 학생별 **Notion 개인 일정 DB**에 별도 행을 복사하던 Make 기능을 앱 서버에서 복제하지 않는다. 중앙 Notion DB가 백업 원본이고 앱이 학생별 공개 화면을 제공하는 방향이다. 개인 Notion DB가 계속 필요하다면 다음 단계 전에 별도 범위를 정해야 한다.
- 노션에서 직접 수동 편집한 앱 관리 일정을 Make가 자동 반영하는 방식은 사용하지 않는다. 앱 관리 기록은 앱에서 변경하고, 노션은 백업으로 사용한다. 앱으로 가져오지 않은 기존 기록은 기존 웹훅 호환을 유지한다.
- 문자 템플릿·본문 생성·미리보기·Bati 발송, 기존 데이터 전체 연결 정합성 조사, 배포 후 Make 중단은 다음 단계로 남아 있다. 현재 Make를 중단하지 않는다.
