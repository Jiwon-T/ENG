# Notion 자료의 앱 상시 저장 절차

## 현재 확인

2026-10-07 연결된 Notion에서 DB_반 관리, DB_시간표, DB_커리큘럼 스키마를 읽어 확인했습니다. 반 관리 상태=Status, 요일=Multi-select. 시간표 상태=Status, 요일=Select, 시간대=Title. 교재 진행도=Status이며 현재 전송하는 시작 전/진행 중/완료 옵션이 존재합니다. 기본 연결과 이 DB들의 형식은 일치합니다. 실패한 운영 요청 로그와 Firestore의 실제 연결 설정은 이번 점검에서 읽지 못했습니다.

## 실행 순서

1. Hotfix 17 적용 후 실패한 반 하나를 다시 시도하고, 화면의 단계·관련 속성·Notion 요청 ID를 확인합니다. 이 정보로 거절된 요청을 고칩니다. 기존 실패 4건의 성공 여부는 그 뒤 각각 확인합니다.
2. 실제 학원/선생님 연결 설정과 DB 목록을 대조하고 서버 저장 자료를 백업합니다. 연결 변경이나 원본 수정은 최초 가져오기와 분리합니다.
3. 서버에서 원본을 커서 끝까지 읽고 별도 Firestore 저장본으로 가져옵니다. 원본 DB ID + 원본 페이지 ID를 고유 키로 사용하고, 원본 수정 시각·가져오기 시각·학원·작성자/담당 연결을 유지합니다. 브라우저에 학생 데이터를 저장하지 않습니다. 조회 때 적용하던 권한 범위를 저장본 조회에도 적용합니다.
4. 학생 → 반·정규 시간표·교재 → 일정 → 과거 일지·성적 순서로 옮깁니다. 단계마다 원본 수/저장본 수, 중복·연결 누락·작성자 미연결을 대조합니다. 미연결 자료에 임의로 사용자 권한을 부여하지 않습니다.
5. 화면 조회를 저장본 우선으로 전환합니다. 기존 API 응답 형태와 권한 검사를 유지합니다. 원본 일지와 앱 작성 일지가 같은 페이지를 가리키면 하나로 연결하고, 더 최신인 앱 수정본·삭제 요청·진행 중인 반영을 원본 사본으로 덮어쓰지 않습니다.
6. 서버 백그라운드 작업으로 원본 변경분을 갱신합니다. 학원/DB 단위 체크포인트·작업 잠금·재시도·전체 대조를 둡니다. 삭제, 대상/담당 범위 밖으로 이동한 자료를 확인하고 앱에서도 숨깁니다. 실패한 배치에서 체크포인트를 앞으로 옮기지 않습니다.
7. 마지막 동기화 시각·오류·미반영 건수를 표시합니다. 첫 로드/탭 이동/직전 수업 조회의 시간과 Notion 요청 수, Firestore 읽기/쓰기를 비교한 뒤 단계별 전환을 확정합니다.

## 기존 기능과 구분

`readMirroredPages`의 Firestore 경로는 요청 시 갱신하는 원본 캐시입니다. 기본값은 memory이며, 켜기만 해서는 위 상시 저장/백그라운드 동기화가 완성되지 않습니다. 현재 ‘기존 앱 반·계획을 노션에 옮기기’는 앱→Notion입니다. 이 버튼으로 Notion→앱 가져오기를 수행하지 않습니다.

이번 전달본은 반영 실패 진단만 구현합니다. 최초 가져오기, 스케줄러 등록, 운영 데이터 이전과 측정은 아직 수행하지 않았습니다.
