# C2 일지 앱 처리 기반 — 운영 미전환

일지의 Firestore 저장·학생/학부모 공개·선택 삭제를 별도 서버 함수로 구현했습니다. 이번 구간은 운영 전환 전 기반 검증입니다. workspace 라우트에 연결하지 않았고, 조회 경로·Notion 호출·화면·운영 자료는 변경하지 않았습니다.

- 저장은 비공개 draft와 변경 이력만 갱신합니다. 이전 공개 내용은 반영 전까지 유지됩니다.
- 반영은 권한·현재 담당·학생 내부 연결·revision을 같은 트랜잭션에서 확인하고 공개 자료와 draft를 함께 기록합니다.
- 같은 학생·날짜라도 서로 다른 draft ID는 독립 기록입니다. 날짜 기준 중복 제거는 하지 않습니다.
- 기존 공개 문서 ID(하이픈 없는 ID 포함), reportIdentity, 학생 내부 ID를 유지합니다. 중복 공개 원본이 발견되면 병합하지 않고 중단합니다.
- 새 앱 일지에는 실제 Notion ID를 null로 둡니다. 공개 식별자는 별도 reportIdentity로 유지합니다.
- 삭제는 선택한 공개 문서만 제거하고 비공개 draft를 보관 상태로 둡니다. 제거 전 공개 내용과 전체 draft를 lessonAppHistory에 원자적으로 남깁니다. 따라서 복원 자료는 있으나 관리자 복원 UI/API는 아직 없습니다.
- 응답 유실 후 같은 revision 반영 재시도는 추가 쓰기 없이 성공합니다. 운영 중 Notion lease·생성 결과 미확정·다른 작성자·담당 해제·오래된 revision은 거부합니다.

남은 다음 구간: 원본 DB별 과거 일지 dry-run, 원본/공개/작성자/회차 대조, 재개 가능한 이전, 삭제·관계 누락 검토, 최종 증거 기반 전환, 위 서버 함수 라우트 연결. 그 뒤 이전 수업/회차와 목록 조회의 Notion 의존을 제거합니다. 현재 배포만으로 Notion 독립 운영이 되지 않습니다.

복구 원칙: 저장 이력은 서버 전용이며 공개 응답으로 전달하지 않습니다. 권한 검증한 복원은 새 revision으로만 실행해야 합니다. 원본 IDs를 유지하고 현재 문서 차이를 대조해야 합니다. 별도 백업 정책은 이전 설계대로 필요합니다.

검증: 새 테스트는 비공개 저장, 하루 두 일지, 재반영 identity, rollback, 담당 해제, 중복 원본 거부, 불확실 Notion 요청 차단, 선택 삭제·이력 보존을 확인합니다. 운영 클라우드 이전과 실제 화면 검증은 실행하지 않았습니다.
