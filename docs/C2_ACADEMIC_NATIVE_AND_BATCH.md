# 성적 관리 · 앱 저장/공개 · 여러 학생 입력 — 2026-10-08

## 구현한 사용자 요청
- 성적 관리의 ‘여러 학생 성적 입력’: 시험 정보(과목/종류/날짜/연도/세부 종류/시험명/만점/기한)는 공통, 원점수/등급/제출 상태/비고는 학생별 입력.
- 한 학생/여러 학생 모두 기존 StudentCombobox 초성 검색 UI 사용. 기존 writableStudents와 담당 과목 범위를 유지.
- 저장 전에도 반영 가능. 단일 입력은 필요한 저장 후 공개, 일괄 입력은 학생별 저장/공개 결과 분리.
- 20명씩 묶어 요청해 반복 인증 요청을 줄임. 최대 선택 100명. 부분 실패는 성공한 학생과 분리하여 같은 ID로 확인/재시도. 완료된 행은 재저장하지 않음.
- 실제 0점/소수 점수 보존, 미제출 점수 null, 만점/날짜/시험 세부 종류는 기존 검증 유지.
- 새 입력 ‘입력 지우기’, 저장된 성적 ‘성적 삭제’. 원본과 이력은 남기고 학생·학부모 공개 자료를 숨김 처리. 앱에 보관된 과거 성적도 소유 권한과 조회 시각 검증 후 삭제.

## Firestore 전환 범위
성적 데이터의 목록 조회·저장·공개·삭제 API는 Firestore 경로를 사용합니다. 일반 성적 요청에서 Notion 성적 DB 조회/저장/삭제를 호출하지 않습니다. 초안과 공개 academicRecords를 구분하고 공개/숨김은 트랜잭션으로 확정합니다. private 비고는 public 성적에 새로 노출하지 않습니다. 기존 공개 ID와 내부 학생 연결을 유지합니다. legacy compact UUID 공개 ID는 재사용하며 충돌한 복사본을 임의로 삭제/병합하지 않습니다.

진행 중 실제 lease는 차단합니다. 만료된 기존 Notion 요청은 기록을 보존해 앱으로 전환하며 revision을 올려 늦은 완료가 최신 상태를 바꾸지 못하게 합니다. 삭제 tombstone/앱 소유 상태로 늦은 Notion·Make 전달의 재공개를 차단합니다. 기존 Notion 문서 자체는 수정/삭제하지 않습니다.

중요: 공통 teacherActor의 담당 권한 확인과 학생 명단 bootstrap은 C-1 실제 전환 전에는 Notion 경로가 남을 수 있습니다. 따라서 ‘전체 앱의 모든 Notion 호출 0’을 의미하지 않습니다. 해당 전환은 기존 학생/수강/담당 대조·활성화 구간에서 해결해야 합니다.

## 과거 성적 이전 도구
관리자(main 학원) 성적 관리의 접힌 ‘과거 Notion 성적 이전’에서:
1. ‘이전 내용 확인 (저장 없음)’: 다음 최대10건의 학생 연결/필드/작성자 확인. 내용 쓰기 0.
2. ‘확인한 다음 10건 가져오기’: 확인한 원본 버전 token 검증 후 명시적 가져오기. 원본 변경 시 적용 거부.
3. 진행 위치와 lease를 서버에 보관하여 중단/실패 후 재개. 성공한 원본은 재실행해도 중복 생성하지 않음.
4. ‘새 대조 순회’: 이전한 내용을 삭제하지 않고 처음부터 다시 확인. 앱 편집/삭제가 있으면 원본을 덮어쓰지 않고 보존.

원본 ID/본문 전체 snapshot/비고/실제 숫자 백분위/검증된 작성자 연결/기존 공개 ID를 보관합니다. 작성자 연결이 모호하면 임의의 선생님으로 배정하지 않습니다. 기존 앱 기록과 원본 관계가 맞지 않으면 검토 오류로 중단합니다. 이 기능은 버튼을 눌렀을 때만 Notion을 읽고 mount/일반 조회에서 자동 이전하지 않습니다.

이전 순회 done은 해당 cursor 순회가 끝났다는 뜻이며 전체 최종 대조 완료가 아닙니다. Notion 편집 중단 시점 이후 새 순회, 원본에서 사라진 자료/관계 해제/모호한 작성자/중복 복사본의 대조가 추가로 필요합니다. 원본 삭제 상태를 추측해 앱 자료를 자동 삭제하지 않습니다.
