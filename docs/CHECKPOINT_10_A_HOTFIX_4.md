# 체크포인트 10 A hotfix 4 — Firestore 중복 초기화 방지

2026-10-06. hotfix 3까지 전체 누적 변경을 포함합니다. B는 보류 중입니다.

## 운영 증거와 재현

ae21cbcb-28cc-463d-968c-12393d4217a6, b74db039-0726-4fa1-8f1c-17d946e76658, 3ee41e59-e814-4561-a38d-b436afb9fa93는 같은 운영 배포의 authentication 단계 WORKSPACE_ERROR/500입니다. 같은 배포에 성공 요청도 기록돼 있으며 이후 초기화 단계 실패가 반복됩니다. 이전 로그는 원래 SDK 예외를 기록하지 않아 세 운영 오류가 특정 예외라고 확정할 수 없습니다.

실제 firebase-admin/Firestore SDK에 기존 helper를 서로 다른 모듈 인스턴스로 두 번 로드한 로컬 재현에서 다음 오류가 발생했습니다:

Firestore has already been initialized. You can only call settings() once, and only before calling any other methods on a Firestore object.

재현은 운영 자격 증명/운영 데이터/네트워크 요청 없이 수행했습니다. 기존 helper의 모듈별 지역 변수는 초기화됐다고 판단하지 못하는 반면 SDK의 앱/DB 레지스트리는 같은 인스턴스를 재사용하여 settings를 두 번 호출했습니다. 여러 서버 번들이 같은 프로세스에서 로드될 때 가능한 결함입니다.

## 수정

- 전역 Symbol 레지스트리로 앱의 각 자격 증명/프로젝트/명시한 DB별 연결을 공유합니다. 모듈이 따로 평가돼도 같은 DB 설정은 한 번만 수행하고 동일한 Firestore/Auth를 반환합니다.
- 임의의 첫 번째 기존 앱을 채택하지 않고 자격 증명/프로젝트에 대응하는 전용 이름의 앱을 사용합니다. 다른 앱 또는 다른 이름의 DB가 섞이지 않습니다. 내부 식별자는 해시이며 비밀키 값을 로그/문서로 남기지 않습니다.
- 이름 있는 FIRESTORE_DATABASE_ID와 4개 필수 설정 검증을 유지합니다. 이미 캐시한 연결이 있어도 환경변수 누락을 허용하지 않고 기본 DB로 대체하지 않습니다.
- 인증 실패 위치를 firebase-initialize/token-verification/workspace-account/workspace-scope로 세분화했습니다. SDK의 안전한 오류 분류(causeCode)도 오류 ID와 함께 기록합니다. Firestore 중복 초기화, 권한, 네트워크, 시간 초과 등을 구별할 수 있습니다. 원시 메시지, 비밀값, 토큰, 사용자 응답을 출력하지 않습니다.
- 기존 토큰 취소/비활성 계정/학원 및 담당 권한 검사, 일지/일정 조회 개선, 학생/리포트 ID와 인증은 유지합니다.

## 검증

전체 테스트 466개 통과, 타입 검사, native Node 서버 import, 프로덕션 빌드 통과. 기존 큰 번들/Firebase mixed import 경고는 남아 있습니다.

추가 5개 테스트:

1. 실제 SDK와 별도 로드된 helper 인스턴스가 같은 이미 설정된 DB/Auth를 재사용합니다. 테스트에서 DB에 settings를 직접 다시 호출하면 SDK가 거부하는 것도 확인했습니다.
2. 다른 기본 앱을 채택하지 않고 DB 이름 변경도 분리합니다.
3. 캐시 상태에서 필수 환경변수 누락을 거부합니다.
4. 안전한 예외 분류에는 원시 개인/자격 증명 값이 들어가지 않습니다.
5. 초기화 실패와 계정 조회 실패 단계를 구별합니다.

SDK 테스트의 인증서 키는 테스트 실행 중 로컬에서 생성한 임시 키이며 운영 키를 사용하지 않습니다. Firestore 읽기/쓰기 요청을 실행하지 않습니다. 실제 재배포 후 화면 복구는 미확인입니다.

## 사용자 재배포 확인

전체 누적 ZIP을 적용해 재배포하고 기존 환경변수를 유지합니다. 선생님방 첫 진입, 탭 이동, 새로고침을 여러 번 확인합니다. 이번 코드 변경에 데이터베이스 재생성/환경변수 변경/공용 DB 재연결은 필요하지 않습니다.

실패가 계속되면 새로운 오류 ID를 알려 주세요. 세분화한 실패 단계와 causeCode로 다음 실패의 실제 원인을 확인할 수 있습니다. 기존 세 오류에 없는 정보를 추측해서 확정했다고 보고하지 않습니다.

운영 배포, IAM/운영 데이터 변경, 문자 발송, Make 중단은 수행하지 않았습니다. B는 다음 사용자 재개 요청 후 진행합니다.
