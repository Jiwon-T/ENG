# 일지 이전 기준일(2026-09-20)과 "Notion에만 보관" 즉시 반영 — 2026-10-09

기준: `c2-managed-app-first`. 운영 이전은 실행하지 않았습니다.

## 배경
- 일지 이전이 너무 오래 걸렸습니다. 학생 관계 속성이 제대로 연결되기 전의 옛 일지까지 모두 읽었고, 그 일지들은 대부분 '학생이 연결되지 않은 일지'로 확인 필요 항목에 쌓였습니다(501건 이상).
- "모두 이전하지 않고 Notion에만 보관"을 눌러도 화면이 바뀌지 않았습니다.
  - 결정만 기록되고, 실제 정리는 다음 "다시 확인"에서 이루어지는 구조였습니다.
  - 다시 확인은 해당 일지를 한 건씩 Notion에서 다시 읽고 학생 관계까지 읽으므로, 501건이면 수십 분이 걸렸습니다.

## 바뀐 동작
- **기준일**: 수업 날짜(`타임 슬롯` 또는 `수업 날짜`)가 **2026-09-20 이후**인 일지만 옮깁니다(학원 결정). 기준일은 코드 상수 `LESSON_MIGRATION_SINCE`입니다.
  - 새로 읽을 때: Notion DB에 날짜 속성이 있으면 Notion 조회 자체에 기준일 필터를 겁니다. 옛 일지는 아예 받지 않습니다.
    - DB마다 실제로 있는 날짜 속성만 필터에 씁니다(DB 구조를 한 번 읽고 기억).
    - DB 구조를 읽을 수 없으면 필터 없이 읽고, 아래의 행별 날짜 검사로 거릅니다.
  - 행마다: 학생 관계를 읽기 전에 날짜부터 봅니다. 기준일 이전이거나 날짜가 없으면 '이전 제외'로 끝내므로 추가 Notion 호출이 없습니다.
  - 다시 확인할 때: 날짜가 기록된 확인 필요 항목은 기준일 이전이면 Notion을 읽지 않고 바로 정리합니다(`evidence: before-cutoff`). 날짜가 없는 항목은 페이지를 한 번만 읽고 날짜로 정리합니다(관계 속성은 읽지 않음).
- **"Notion에만 보관" 즉시 반영**:
  - 학생 미연결·학생 2명 이상·과목 오류처럼 '옮기지 않는' 결정은 누르는 순간 확정됩니다(`status: acknowledged`). Notion을 다시 읽지 않고, 확인 필요 목록과 전환 조건에서 바로 빠집니다.
  - 결정 기록(누가·언제·어떤 버전)은 그대로 남습니다.
  - 그 일지가 나중에 Notion에서 바뀌면 버전이 달라지므로, 다음 스캔에서 다시 확인 필요로 열립니다.
  - '옮기는' 결정(작성자 미확인 등)은 데이터를 새로 저장해야 하므로 지금처럼 다시 확인 때 반영합니다.
- **보존**:
  - 이미 옮겨진 기준일 이전 일지는 지우지 않고 그대로 둡니다.
  - Notion 원본도 그대로입니다.
- **남은 영향**: 일지를 앱 전용으로 바꾼 뒤에는 기준일 이전이면서 아직 옮기지 않은 일지가 앱 화면(일지 조회·이전 수업·회차·학부모 리포트의 지난 기록)에 보이지 않습니다. 원본은 Notion에서 볼 수 있습니다.
- Notion 일시 오류(429·5xx)는 DB 구조를 읽을 때도 기존처럼 자동 재시도 대상입니다.

## 검증
- lint 통과, 테스트 742/742, build 통과, Node 서버 import 통과.
- 새 `tests/lessonMigrationCutoff.test.ts` 3건:
  - 기준일 당일 일지는 이전되고, 그 전날 일지(학생 없는 일지 포함)는 확인 필요 없이 제외되며 관계 속성을 읽지 않음
  - 날짜 속성이 있는 DB에는 Notion 조회에 기준일 필터를 걸음
  - "Notion에만 보관"이 Notion 호출 없이 즉시 확정되고, 다음 스캔에서도 확정 상태를 유지함
- 기존 일지 이전 테스트는 기준일보다 앞선 가짜 날짜를 쓰므로, 테스트 안에서만 기준일을 낮춰 기존 동작을 그대로 검증합니다.
