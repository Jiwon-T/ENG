# 체크포인트 9 긴급 수정 4 — 노션 일지 저장 충돌 해결

일지 조회 및 작성 화면에서 NOTION_EDIT_CONFLICT 기록에 앱·노션 내용 비교해서 해결 버튼을 제공합니다. 항목별 앱의 저장 요청 값과 현재 노션 값을 비교한 뒤 앱 내용 유지 또는 현재 노션 내용 유지를 선택하고 확인 체크 후 반영합니다. 학생·과목·노션 페이지 ID를 유지하고 같은 초안의 새 수정 차수로 발행하므로 기존 리포트 식별자를 유지합니다.

비교 요청은 원격 자료를 변경하지 않습니다. 선택 반영은 비교 토큰과 앱 수정 차수, 노션 수정 시점·속성·기존 요청 상태를 재검사합니다. 활성 발행 임대·삭제 중·다른 학생·다른 과목·다른 앱 기록 ID·접근 권한 위반·복수 앱 기록 ID 페이지는 차단합니다. 최신 비교 결과를 확인한 사용자 선택에 한해서 오래된 immutable intent를 종료하고 최신 원격 수정 시점으로 새 요청을 준비합니다. 이후 기존 writer도 저장 직전에 수정 시점을 다시 검사합니다. 비교 후 노션이 다시 바뀌면 충돌을 재표시합니다.

현재 노션 내용 선택은 앱이 관리하는 일지 입력을 가져옵니다. 노션만의 기타 속성은 기존 반영 코드가 건드리지 않습니다. 앱에만 있는 다음 수업 계획 등 노션 속성이 없는 항목은 유지합니다. 노션 내용에 앱 필수 입력·점수·시간 기준을 만족하지 않는 값이 있으면 선택을 비활성화합니다. 먼저 노션을 정리하고 비교 화면을 다시 열거나 앱 내용을 선택합니다.

선택 후 반영이 중단되거나 응답이 유실되면 새 페이지를 만들지 말고 기존 초안을 새로고침해 저장 결과 확인·재시도를 사용합니다. 비교 화면은 계정 변경 후 늦은 응답을 표시하지 않습니다. 문자 발송은 호출하지 않습니다.

이전 체크포인트와 긴급 수정 모두 포함합니다. 이번 작업에서는 실제 이현준 학생의 운영 일지를 수정하거나 배포하지 않았습니다. 사용자가 수정본을 배포한 뒤 유지할 내용을 선택해 기존 충돌을 해결합니다.
