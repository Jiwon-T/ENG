# 입학 원서 기반 신입생 입력 폼 제안

첨부 입학원서.jpg를 직접 확인했다. 현재 등록 폼의 이름·학교·학년·연락처·호칭·수강료·납부기한·과목별 수강·담당·반 선택을 유지하면서 하나의 팝업으로 구성하는 것을 제안한다.

## 기본 화면: 학생 및 수강 등록

학생 이름, 학교·학년, 학생 연락처, 보호자 연락처·이름, 학생 호칭을 먼저 배치한다. 이름은 자동으로 이름(학교학년) 형식의 노션 제목으로 만들며 문자 호칭은 독립적으로 유지한다. 연락처가 없으면 빈 값으로 보관하고 임의 번호나 PIN을 만들지 않는다.

바로 아래 수강 과목별 담당 선생님·반·시작일·등록/대기 상태를 지정한다. 반 선택 시 시간표를 읽기 전용으로 보여 주며 배정 시간과 학생이 가능한 시간을 비교할 수 있게 한다. 과목별로 반을 선택하면 기존 반 명단을 덮어쓰지 않고 학생 소속반 관계로 연결한다. 수강료·납부기한은 기존 항목을 유지한다.

## 접어 두는 상세 입력

| 원서 구역 | 입력 방식 | 보관 제안 |
| --- | --- | --- |
| 생년월일·주소·알게 된 경로 | 날짜, 주소 텍스트, 경로 선택 및 기타 입력 | 학생 기본 정보 추가 속성; 생년월일·주소는 선택 입력 |
| 이전 학습 이력 | 기간·학원명·사용 교재·학습 내용의 추가 가능한 행 | 별도 학생 상담 기록 |
| 현재 수준 | 국어·영어·수학·과학별 내신/모평/진단평가, 점수와 등급을 별도 입력 | 입학 당시 수준 기록; 실제 시험일을 모르면 날짜를 만들지 않음 |
| 목표 | 학습 목표·희망 성적·진학 목표 자유 입력 | 학생 상담 기록 |
| 수업 가능한 요일·시간 | 요일 여러 개와 가능한 시간대 여러 행 | 상담 기록; 정규 시간표와 별도 |
| 참고 사항 | 요청 사항·지도 시 참고할 내용 | 상담 기록; 수업일지 특이사항과 별도 |
| 동의·서명 | 원서 동의/미동의/미확인, 확인일·확인 담당자, 서명 원서 보관 여부 | 원본 확인 기록; 앱 체크가 종이 서명을 대신했다고 표시하지 않음 |

입학 성적은 공식 성적 그래프에 즉시 합산하지 않고 입학 당시 참고 기록으로 두는 것을 권한다. 정식 성적 등록은 기존 성적관리에서 시험 종류·일자를 확인한 후 수행한다.

## 저장과 공개 범위

기본 정보만으로 등록 초안을 저장할 수 있고 상세 상담 정보는 나중에 입력한다. 최종 확인에서는 학생 이름·연락처·과목·담당·반을 함께 보여 준다. 중복 의심 학생은 기존 학생을 선택해 이어 등록하도록 안내하고 이름만 같은 학생을 자동 병합하지 않는다.

학생/수강 기본값은 현재 DB_학생 관리·DB_수강에 연결한다. 긴 학습 이력·목표·시간·참고·원서 확인은 학생 관계가 있는 별도 상담/입학 기록으로 보관한다. 이 신규 DB 및 속성은 구현 시 실제 스키마를 확인해 정해야 한다. 관리자·원장과 필요한 담당 교사의 조회 범위를 구분하고, 주소·상담·입학원서·동의 정보는 학생·학부모 공개 리포트에 자동으로 포함하지 않는다.

이번에는 제안만 작성했다. 폼·노션 운영 속성·데이터는 변경하지 않았다.
