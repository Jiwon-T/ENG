# 수업일지 중복 표시·시험범위·입학 상담 폼 · 2026-10-05

체크포인트 8 및 hotfix 1 전체 코드에 누적 적용했다. 체크포인트 9를 시작하지 않았다.

## 이현준 학생의 중복 표시

- 실제 중앙 노션의 10/5 이현준 기록에서 앱 기록 ID 64fcb977-751c-4aac-a5dd-bb5223d385e8, 노션 페이지 3f00d0f1-c79a-8194-b425-e426ab16a821, 학생 관계 3e20d0f1-c79a-80a5-bed9-faef008b94c5를 읽기 전용 확인했다.
- 원본 행 조회에서 앱 기록 ID를 버리고, 목록 병합에서 notionPageId만 비교하던 문제를 수정했다. 노션 생성은 완료됐지만 앱의 페이지 주소 연결이 늦거나 응답이 유실된 상태에서는 동일 요청을 앱 행과 노션 행으로 각각 표시할 수 있었다.
- 조회한 노션 행에 앱 기록 ID를 보존한다. 주소가 아직 없는 앱 행이라도 앱 기록 ID·학생·과목·작성자·학원이 일치하면 한 항목으로 표시한다. 저장 대기 상태와 앱의 수정 입력은 유지하며 원래 앱 ID로 재시도한다.
- 같은 날짜/이름이라는 이유로 다른 수업을 합치지 않는다. 앱 기록 ID가 중복된 노션 행, 다른 학생·작성자·학원·과목은 자동으로 합치지 않는다.
- 리포트 임시 문서에서 노션 문서로 옮길 때 기존 노션 복사본이 먼저 있어도 앱의 공개 리포트 식별자를 유지한다. 모든 후보의 학생·앱 소유 요청·revision을 검증한 뒤 거래 안에서 동일 요청 임시 문서만 정리한다. 잘못 연결된 다른 학생 문서는 삭제하지 않는다.
- 실제 Firestore의 두 항목 내용과 실패 요청에 도구로 접근하지 못했으므로 운영 데이터의 두 문서를 삭제하거나 복구 완료했다고 주장하지 않는다. 새 코드 배포 후 기존 일지의 저장 결과 확인·재시도로 동일 앱 ID의 노션 행을 연결한다. 두 항목의 앱 ID가 서로 다르면 별도 기록으로 유지하므로 추가 확인이 필요하다.

## 시험범위

- 실제 수업 일지 DB의 시험범위 텍스트 속성을 확인했다.
- 단일 및 여러 학생 작성 모두 과제 바로 아래 선택 textarea를 추가했다. 공통 입력·이어 작성·직전 일지 채움에도 시험범위를 보존한다. 사용자가 바꾼 입력을 늦은 조회가 덮어쓰지 않는다.
- 시험범위는 수업 내용/과제에 섞지 않고 별도 노션 rich_text 속성으로 저장한다. 빈 입력은 새 revision의 기존 시험범위를 비운다. 글자 수는 5,000자 이하이며 Notion 텍스트 길이에 맞춰 분할한다.
- 시험범위가 없는 다른 과목 DB는 빈 값일 때 기존 발행을 계속 허용한다. 내용이 있다면 텍스트 속성이 필요하다고 안내한다. 새 속성이 추가되었다는 이유로 옛 미완료 요청의 불변 속성을 바꾸지 않는다.

## 입학·상담 폼

- 학생관리 → 신입생 등록 창에 접힌 입학 원서·상담 정보 영역을 구현했다. 현재 이름·학교·학년·연락처·담당·반·수강료 입력은 유지한다.
- 생년월일·주소·알게 된 경로, 이전 학습 기간·학원명·사용 교재·내용, 국어/영어/수학/과학별 내신·모평 점수와 등급 및 진단평가, 목표·가능 요일/시간·참고 사항, 원서 동의 상태·확인일·서명자·서명 원서 보관 여부를 입력한다.
- 상세 입력은 모두 선택이다. 기본 정보만으로 등록 초안을 저장할 수 있다. 상세 항목은 노션 반영 전에 채운다. 노션 생성이 시작되면 기존 등록 요청의 불변 잠금 규칙을 유지한다. 이번 폼은 신입생 등록에 통합한 형태이며 기존 학생의 별도 반복 상담 기록 편집 기능은 포함하지 않는다.
- 상담 입력은 기존 서버 전용 등록 요청 문서에 저장된다. 학생 노션 페이지 최초 CREATE의 본문(children)에 읽기 쉬운 항목별 문단으로 함께 백업한다. 별도 상담 DB나 두 번째 학생 페이지를 만들지 않아 추가 DB 설정이 필요 없다. 실제 운영 DB에 새 속성이나 페이지를 미리 만들지 않았다.
- 같은 최초 생성 요청의 응답 유실 시 기존 앱 등록 ID로 학생 페이지를 찾아 복구하며 상담 본문을 다시 붙이거나 새 페이지를 만들지 않는다. 수강 정보는 기존 DB_수강 관계로 저장한다.
- 입학 당시 수준은 참고 자료이며 공식 성적 그래프에 자동 합산하지 않는다. 미입력은 null이며 실제 0점은 보존한다. 상담 정보·주소·원서 확인은 공개 학생/학부모 리포트 DTO에 포함하지 않는다.
- 원서 동의 확인 상태를 기록하는 UI이며 체크가 원본 서명을 대신한다고 표시하지 않는다. 원서 사진 첨부·전자서명·OCR은 포함하지 않는다. 긴 학습 이력은 이번 기본 폼에서 기간/학원/교재/내용 각 한 항목으로 기록한다.

## 검증과 재개

전체 테스트 344개, 타입 검사, 프로덕션 빌드 통과. 신규 테스트는 앱 ID 중복 표시, 잘못된 식별 병합 금지, 진짜 중복 노션 ID 보존, 임시 공개 ID 유지와 충돌 문서 보존, 시험범위 저장/초기화/늦은 채움/옛 불변 요청 호환, 상담 날짜/점수/중복과목 검증, 상담 원문 분할, 공개 범위, 신입생 생성 응답 유실 시 상담 중복 방지를 검증한다. 기존 번들 크기 경고는 유지된다.

배포·운영 노션/Firestore 수정·실제 문자 발송·Make 시나리오 변경은 하지 않았다. 사용자는 ZIP 배포 후 이현준 기존 항목의 재시도 및 한 항목 표시, 시험범위 입력과 실제 노션 속성, 신입생 등록 초안의 상담 항목 저장과 노션 페이지 본문을 확인한다. 체크포인트 8 Bati 서버 설정 계약 확인 요구는 그대로 유지된다.
