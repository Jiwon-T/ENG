# 중단 학생의 반 연결을 정상 이력으로 처리

체크포인트 9 및 핫픽스 1~6 전체를 포함합니다. 이번 구간은 새 요청의 1번만 구현했습니다.

- 과목 수강이 중단이면 연결된 반이 진행 중이든 중단이든 CLASS_ASSIGNMENT_MISMATCH를 만들지 않습니다. 다른 학생이 있거나 새 학생을 기다리는 진행 중 반은 정상입니다. 이 상태를 별도 반복 확인 항목으로 추가하지 않습니다.
- 수강 변경에서 중단 시 기존 소속반 연결을 유지할 수 있습니다. 현재 반 담당이 이전 학생 담당과 달라도 퇴원 이력 유지가 가능합니다. 중단 상태에서 새 반 연결을 추가하지 못하도록 서버에서 검증합니다. 대기 상태의 반 배정 제한은 유지합니다.
- 등록에서 중단으로 변경을 저장할 때 현재 연결된 진행 중 반의 완전한 대상 학생 목록이 이 학생 한 명뿐이면 한 번 확인합니다. 확인을 누르면 반을 유지하고 학생만 중단합니다. 반도 중단하려면 취소 후 기존 반 관리에서 상태를 변경합니다. 반은 자동 변경하지 않습니다. 반 연결 해제 선택 여부와 무관하게 유일한 학생의 중단을 확인합니다.
- 다른 학생이 있거나 이미 중단된 반, 이미 중단된 학생 수정, 같은 저장 요청 복구·재시도에는 이 확인을 반복하지 않습니다. 목록이 잘린 경우에는 유일한 학생이라고 단정하지 않습니다.
- 등록 학생의 실제 담당 불일치, 누락 원본, 중복 수강, 잘못된 날짜 등 독립적인 문제는 계속 점검합니다.

검증: 테스트 402개 통과, TypeScript 검사, Vite 빌드, 서버 네이티브 import 검사 통과. 빌드의 기존 chunk 크기 및 firebase 혼합 import 경고는 남아 있습니다. 테스트는 가짜 Notion/Firestore를 이용했으며 운영 노션·데이터·배포·Make를 변경하지 않았습니다.
