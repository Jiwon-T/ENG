# 앱–노션 전환 재개 기록: 체크포인트 5 (학생 정보 수정·PIN 갱신)

기준: ENG (6).zip → 체크포인트 1~4 및 수업일지 긴급 수정 → 이번 체크포인트 5. 이 ZIP은 전체 누적 코드다.

## 이번 단계 완료

- 학생 관리 카드에 관리자/원장 전용 정보 수정 팝업을 추가했다. 기존 학생과 노션에 반영한 신입생 모두 같은 카드에서 수정한다. 초기 등록 요청의 복구 화면은 계속 읽기 전용으로 보존하고 수정 위치를 안내한다.
- 읽기·수정 범위: 학생 표시 이름(기존 Notion 제목 그대로), 학교, 학년, 학생/보호자 연락처, 보호자 이름, 학생 호칭, 수강료, 납부기한. 기존 제목을 이름/학교로 임의 분해하지 않는다. 학교·학년 변경 시 표시 이름도 확인하도록 안내한다. 수강 상태·담당·반은 이번 수정 폼에서 변경하지 않는다.
- GET student-profile, POST save-student-profile, POST discard-student-profile을 기존 workspace API에 추가했다. 새 Vercel 함수는 추가하지 않았다. main 학원의 확인된 학생 DB만 사용한다.
- 일반 교사는 이 학생 상세 연락처 API를 사용할 수 없다. 원장은 활성 학원 학생 소속이 필요하다. 관리자도 명시적으로 다른 학원 소속인 학생은 수정할 수 없다. Notion 페이지 원본/보관 상태/학생 ID 및 변경 속성 스키마를 확인한다.
- 변경한 속성만 Notion PATCH한다. 수강·소속반·문자 템플릿·등록 ID 등 다른 속성을 덮어쓰지 않는다. 저장 직전 페이지 편집 시각을 재조회해 확인하고 저장 뒤 실제 값을 재조회한다. Notion에는 원자적 조건부 PATCH가 없으므로 외부 수동 편집과의 모든 경쟁을 원천 차단하는 것은 불가능하다.
- teacherStudentEdits에 요청 UUID, 입력, 변경 전 값, 기대한 편집 시각, 진행 상태, 3분 lease, PATCH 시도 여부를 서버 전용으로 저장한다. Firestore 직접 접근을 차단했다. 같은 학생의 진행 중인 다른 요청이나 같은 UUID의 다른 입력은 거절한다.
- 부분 실패/응답 유실 후 같은 요청으로 현재 Notion 값을 읽어 복구한다. 변경 대상 값이 이미 일치하면 PATCH를 반복하지 않는다. 관련 없는 수동 Notion 변경은 유지한다. 결과가 불명확하고 대상 값이 일치하지 않으면 자동으로 덮어쓰거나 요청을 취소하지 않는다.
- PATCH하지 않았거나 확정된 4xx 거절로 반영되지 않은 요청은 미반영 수정 요청 취소 버튼으로 취소할 수 있다. 타임아웃/5xx 후에는 결과 확인만 가능하며, 계속 일치하지 않으면 원격 기록/실행 결과 확인이 필요하다. 편집 가능한 확정 실패를 취소하면 최신 Notion 값을 다시 읽는다.
- 이름 메타데이터는 기존 migrateStudentMapping을 사용한다. 현재 lease와 학원 권한을 같은 Firestore 거래에서 확인하는 래퍼를 적용해 만료된 실행이 새 실행의 이름 메타데이터를 덮어쓰지 못한다. internalStudentId·Firebase 소유권·학생 계정 이름·리포트 주소는 유지한다.
- 보호자 번호가 바뀌면 요청 저장과 동시에 기존 모든 reportSlugs의 PIN 해시를 비워 인증을 잠그고 authVersion을 1회 올려 기존 세션을 즉시 무효화한다. 전체 번호가 다르면 뒤 4자리가 같아도 기존 세션을 무효화한다.
- Notion 반영 및 앱 연결을 확인한 뒤 새 번호 뒤 4자리의 HMAC 해시를 저장하고 인증을 연다. 재시도 시 authVersion을 다시 올리지 않는다. 번호를 비우면 PIN 인증은 계속 중지되고 리포트 주소/활성 상태 자체는 유지한다. 번호를 바꾸지 않은 수정은 PIN/authVersion/잠금 카운터를 유지한다.
- 연락처 반영 중 새로운 리포트 주소 발급을 같은 edit 문서를 읽는 거래에서 차단한다. 완료 후에도 변경 전 전화번호를 읽어 온 오래된 발급 요청은 거절한다. 주소 변경은 기존 인증 잠금 마커를 복사하므로 새 주소도 확인 완료 전 인증되지 않는다.
- 팝업을 닫아도 서버에 접수한 요청은 남는다. 다시 열면 미완료 입력과 결과 확인 버튼을 복구한다. 연락처를 브라우저 저장소에 저장하지 않는다. 계정/팝업 변경 시 늦은 응답을 무시하고 목록 갱신도 계정·요청 세대별로 보호한다.

## 검증과 실제 실행 범위

전체 테스트 274개, TypeScript 검사, 프로덕션 빌드 통과. 실제 workspace 상세 읽기·저장 액션, 접근 권한·입력 위조 차단, 기존 parent session 검증 함수에 의한 세션 무효화, PIN/주소/계정 보존, 동일 뒷자리 번호 변경, 번호 삭제, 확정 실패 취소, 응답 유실 복구, 중복 요청, 거래 실패, 만료 lease의 늦은 실행, 오래된 재전송, 관련 없는 원격 변경 보존, 새 링크 발급의 연락처 동기화 잠금을 가짜 HTTP 및 거래형 Firestore로 검증했다.

실제 운영 학생/연락처/PIN을 수정하지 않았다. 실계정 클릭·배포·병합·문자 발송·Make 변경은 수행하지 않았다. 사용자가 배포 후 학생 수정과 보호자 인증 왕복을 확인해야 한다. 기존 NOTION_INTEGRATION_TOKEN, NOTION_STUDENT_DATABASE_ID, PHONE_PIN_PEPPER, PARENT_SESSION_SECRET을 사용하며 새로운 비밀 환경변수는 추가하지 않았다.

## 현재 완료 범위

- 신입생 앱 저장 → 노션 학생/수강 생성 → 담당/소속반 최초 배정 → 기존 식별 매핑/학원 소속/수강 연결.
- 기존 및 신규 학생의 기본 정보/연락처 수정과 보호자 PIN·세션 갱신.
- 이전 긴급 수정 포함: 수업 내용 필수 표시 및 빈 내용 반영 차단(단일·반별 모두). 작성 중 초안은 빈 내용 보존 가능. 특이사항은 기존 Notion 특이사항에 기록하고 앱 특이사항과 호환. 단일 일지 팝업은 반영 중에도 닫을 수 있으며 반영 뒤 목록 갱신은 별도로 진행한다.

## 다음 단계 (사용자의 재개 지시 후)

1. 이 기록과 docs/APP_NOTION_SCHEMA.md부터 읽는다.
2. 기존 학생의 수강 상태/시작일/중단일, 담당 선생님, 반 변경을 추가한다. 기존 학생·수강 행의 ID와 등록 ID를 보존하고 단일 수강 행 및 실제 과목별 스키마를 사용한다.
3. 학생 소속반의 양방향 관계를 통해 새 반 연결·제외를 처리한다. 공유 반 학생 명단을 오래된 값으로 덮어쓰지 않는다. 신규 담당 배정 및 담당 제외 후 교사의 접근 범위를 검증한다.
4. 다른 선생님의 담당이나 이번 단계에 포함하지 않은 과목·관계를 지우지 않도록 변경 범위를 정한다. 노션의 휴직/중단/학원/과목이 바뀐 배정은 확인 후 처리한다.
5. 다음 묶음을 검증한 전체 ZIP을 전달하고 멈춘다. 사용자의 재개 지시에 따라 이어간다.

## 이후 단계와 유지 요구

- 일정·성적·수업일지의 남은 Make 의존성 제거 및 앱 리포트 직접 반영. 여러 학생 일정의 제외/삭제 취소, 늦은 Make 요청의 최신 앱 기록 덮어쓰기 방지.
- 문자 템플릿·본문 생성·미리보기·Bati 서버 발송. 실제 발송은 별도 버튼과 최종 확인 후에만 실행하며 불명확한 응답은 재전송 잠금.
- 사용자 배포 검증 후에만 기존 Make 시나리오 중단 및 백업 보관.
- 복제 노션 수업일지 리셋 기능 제외. 기존 데이터 연결과 리포트 링크 보존. 파스텔 핑크 단색 UI 유지. 학생 관계형 사용.
- 이미 노션 생성이 시작된 신입생 입력은 고정한다. 타임아웃/5xx 후 중복 생성하지 않고 앱 등록 ID로 복구한다.
- node_modules와 dist는 ZIP에서 제외한다. npm ci 후 npm test, npm run lint로 확인하고 다음 단계부터 재개한다.
