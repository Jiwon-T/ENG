# 체크포인트 9 — 연결 정합성 점검

최근 핫픽스 1·2와 체크포인트 8 전체 코드를 포함합니다.

## 사용 방법
관리자 설정 → 연결 정합성 점검 → 현재 연결 점검.
관리자·원장만 서버에서 허용합니다. 현재 지원 대상은 main 학원과 기존 DB_학생 관리입니다. 원장은 활성 학원 소속 학생만, 관리자는 해당 원본의 레거시 학생도 점검합니다.

## 검사 범위
- 학생 매핑의 정규·레거시 식별자 충돌, 여러 계정 연결, 계정 역할과 양방향 연결.
- 노션 학생 원본, 수강 행 중복·누락, 여러 학생 관계, 담당 선생님 원본, 날짜 순서.
- 소속반 원본, 반의 과목·담당과 수강 상태·담당의 일치.
- 활성 리포트 주소 중복·학생 불일치, 앱 수강 연결 중복.
- 같은 초안·teacherAppRevision의 앱 리포트 중복, 같은 앱 기록 ID의 노션 일지 중복.
- 등록·정보 수정·수강 변경·일지·문자의 미완료 상태, 교직원 계정 역할·노션 연결.
- Bati 주소·본문 매개변수의 설정 형식. 설정 여부만 반환하고 주소·토큰은 반환하지 않습니다.

점검은 모든 페이지를 조회하며 미러 동기화 함수를 호출하지 않습니다. POST /query는 읽기 요청입니다. 데이터 쓰기·자동 병합·수신번호/PIN/본문 노출을 하지 않습니다. 원본별 실패와 관계 has_more는 검사를 미완료로 표시합니다. 생략한 원본을 정상으로 판정하지 않습니다. 버튼을 누를 때만 실행하고 결과를 공유 캐시에 저장하지 않습니다. 계정 변경·화면 해제 후 늦은 응답은 표시하지 않습니다.

미완료 작업은 기존 작업 화면의 결과 확인·재시도를 이용합니다. 문자 sending/uncertain은 Bati에서 접수 여부 확인 전 재발송하지 않습니다. 이름·날짜만으로 일지나 학생을 합치지 않습니다.

## 문자 권한·설정 보완
- 문자 준비 트랜잭션에서 학원 소속과 연락처 변경 작업을 다시 읽어 검사합니다.
- 발송 트랜잭션에서 삭제된 소속도 일반 교직원에게 차단합니다.
- 비활성 소속은 관리자에게도 차단합니다.
- BATI_MESSAGE_PARAM이 보호자연락처와 같거나 제어문자/앞뒤 공백을 포함하면 차단합니다. 수신번호가 본문으로 덮어써지는 설정을 막습니다.

## 한계와 배포 후 확인
점검은 실행 시점의 개별 조회 결과이며, 여러 시스템의 원자적 스냅샷은 아닙니다. 현재 전체 컬렉션과 원본을 읽으므로 데이터가 매우 커지면 분할 점검이 필요합니다. 학생과 반의 모든 양방향 관계, 성적·일정 전체 기록, Bati 실제 응답 계약을 완전히 검증하는 감사는 아닙니다.

이번 작업에서 운영 Firebase·노션 데이터 점검 결과를 취득하거나 변경하지 않았습니다. 구현 검증에는 격리된 테스트 데이터를 사용했습니다. 배포 후 관리자/원장 계정으로 실제 결과를 확인해야 합니다. Bati 정확한 본문 매개변수와 접수 응답 계약은 여전히 운영 설정 확인이 필요합니다. 실제 문자 발송·배포·Make 변경은 하지 않았습니다.

사용자가 배포 후 일지·일정·성적·등록·리포트·문자 흐름을 확인한 뒤에만 대체된 Make 시나리오를 백업하고 중단합니다. 복제 일지 리셋은 제외합니다.
