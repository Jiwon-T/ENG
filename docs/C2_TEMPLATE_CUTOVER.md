# 문자 템플릿 앱 전용 전환 스위치 — 2026-10-09

기준: `c2-notion-dependency-audit`. 운영 실행·배포·전환은 하지 않았습니다.

## 왜 바꿨나
지금까지 템플릿 읽기 전환은 환경변수 `MESSAGE_TEMPLATE_READ_MODE=firestore`를 바꿔 다시 배포해야 했고, 가져오기·점검이 끝났는지 확인하는 장치도 없었습니다. 또 앱에서 고친 템플릿은 별도 반영 작업기(worker)가 Notion에 써야 "동기화 완료"가 되는 구조라, Notion을 끊을 수 없었습니다.

## 사용자 조작
설정 → 문자 템플릿 관리를 열면 **문자 템플릿 앱 전환** 카드가 보입니다.
- 점검표 6개를 자동으로 판정합니다: 최초 가져오기 / 15분 이내 변경 가져오기 / 15분 이내 원본 점검 / 충돌 없음 / 접근 확인 안 된 템플릿 없음 / 진행 중 작업 없음.
- `가져오기·점검 후 앱 전용으로 전환` 한 번이면 됩니다. 화면이 기존 자동 이전을 그대로 실행하고(가져오기 + 원본 점검), 서버가 결과를 한 트랜잭션으로 다시 확인한 뒤 전환합니다.
- 충돌이나 접근 미확인처럼 사람이 판단해야 하는 항목이 있으면 버튼이 비활성화되고, 아래 템플릿 목록에서 정리하도록 안내합니다.
- `전환 해제`: 앱 템플릿 값은 그대로 두고 이전 방식으로 돌아갑니다.

## 서버
- `api/_lib/messageTemplateAuthority.ts`
  - `templateAppActive`: 전환 표식과 같은 해시의 검증 기록이 함께 있을 때만 true입니다. 손으로 만든 표식은 무시합니다.
  - `activateTemplateApp`: 위 조건을 트랜잭션 안에서 다시 확인합니다. 이때 **Notion 반영을 기다리던 앱 수정**은 `app`(앱 저장 완료)으로 확정하고, 대기 중이던 반영 작업을 `not-needed`로 정리합니다. 반영 작업기를 배포하지 않았어도 "대기"로 남는 템플릿이 없습니다. 지금 실행 중인 작업이 있으면 전환하지 않습니다.
  - `deactivateTemplateApp`: 표식만 끄고 이력을 남깁니다.
- 전환 후 동작(`messageTemplateStore.ts`)
  - 문자 화면과 템플릿 목록은 Firestore만 읽습니다(`templateReadsFromApp`). 환경변수는 예전 강제 설정으로만 남겨 둡니다.
  - 저장은 같은 트랜잭션에서 바로 확정됩니다(`status:'app'`). 같은 요청을 다시 보내도 수정이 하나만 생기도록 접수 기록을 남깁니다.
  - Notion 가져오기·dry-run·원본 점검·재반영은 거부합니다(`TEMPLATE_APP_ACTIVE`). 반영 작업기도 Notion을 부르지 않고 작업만 정리합니다.
  - 해제 뒤에는 `app` 상태 템플릿도 다시 수정할 수 있고, 수정하면 예전처럼 Notion 반영 작업이 생깁니다.
- 동작: `template-cutover-status`, `template-cutover`, `template-cutover-deactivate`(기존 template 경로, 관리자만).

- 앱 전용일 때는 Notion 가져오기·dry-run·점검 버튼을 숨깁니다. "앱에 저장", "앱 저장 완료"처럼 앱 기준으로 표시합니다.
- 노드 테스트가 컴포넌트를 직접 렌더링하므로, CSS는 컴포넌트가 아니라 `TeacherWorkspace.tsx`에서 한 번 불러오게 바꿨습니다.
- 미리보기에서 3가지 상태(점검 필요·전환 가능·앱 전용)를 확인했습니다. 캡처는 `lesson-cutover-proof/7~9`입니다.

## 검증
- lint 통과, 테스트 707/707, build 통과, Node 서버 import 통과.
- 새 `tests/messageTemplateAuthority.test.ts` 4건:
  - 전환 조건(가져오기 미완료·오래된 점검·충돌·접근 미확인·권한·확인 없음)과 정상 전환
  - 대기 중 수정이 앱 저장으로 확정되고, 전환 후 저장이 즉시 확정되고, 같은 요청 재시도가 하나로 처리되고, Notion 작업이 거부되며 Notion 호출이 0회
  - 손으로 만든 표식 무시, 해제 후 값 보존과 이전 방식 복귀
  - 화면 버튼 흐름(자동 이전 → 전환 → 상태 → 해제)
- 기존 테스트 1개는 가져오기 전 전환 여부 확인으로 문서 읽기가 1회 늘어난 만큼만 맞췄습니다.

## 운영 메모
- 전환 버튼을 누르기 전에 Notion 템플릿 직접 수정을 멈춰야 합니다. 화면 확인창에도 안내합니다.
- 기존에 `MESSAGE_TEMPLATE_READ_MODE=firestore`로 배포했다면 그대로 두어도 됩니다. 새로 설정할 필요는 없습니다.
- 템플릿 반영 작업기(Cloud Run)는 전환 후 필요 없습니다. 실제 중단은 사용자가 결정합니다.
