# C-1 첫 묶음 — 학생·수강·담당 권한의 Firestore 운영 경로

2026-10-08. 사용자의 최신 지시로 목표를 **Notion 독립 운영**으로 변경했습니다. 지속 양방향 동기화는 필수가 아닙니다. B의 템플릿 파일럿과 기존 Notion 경로는 이력/전환 전 호환을 위해 보존하며 임의 삭제하지 않습니다.

## 완료한 코드 범위와 아직 완료하지 않은 범위

이번 묶음은 기존 학생의 목록/상세 조회·정보 수정, 기존 수강의 상태/담당 변경, 선생님 담당 권한 판정과 부여의 Firestore 경로입니다. Notion ID는 출처/기존 연결 값으로 유지합니다. 새 운영 계정이나 리포트 주소를 자동 생성하지 않습니다.

**운영 이전과 C-1 전체 완료는 아닙니다.** 반·정규 시간표의 완전한 읽기/쓰기/연결 이전, 앱 전용 신규 학생 등록은 다음 C-1 묶음입니다. 일정·일지·성적·문자 본문 준비/발송·리포트 전체의 독립 운영도 후속 구간입니다. 이번에는 기존 연락처를 소비하는 문자·리포트 경로가 앱의 최신 이름/PIN을 오래된 Notion 값으로 덮어쓰지 않도록 연결했습니다. 실제 문자는 발송하지 않았습니다.

현재 학원처럼 학생에 반 연결이 있으면 반 전환 준비가 끝날 때까지 최종 전환은 거절됩니다. `academyClassAuthority/main.active`는 다음 반/시간표 이전 코드가 검증 후 기록할 조건입니다. 이를 수동으로 만들어 검사를 우회하지 않습니다. 따라서 이 ZIP만으로 지금 학원을 독립 운영 완료로 표시하면 안 됩니다.

## 기존 연결과 자료 저장

- `academyDirectorySources`: main 학원 + 기존 DB + 정규화한 원본 UUID로 한 번 저장합니다. 학생·선생님·수강의 필요한 속성을 보관하며 사용자별 복제하지 않습니다. 원본 관계가 잘리면 pagination으로 끝까지 읽고 상한 초과/불완전 응답은 저장하지 않습니다.
- `academyDirectorySync`: 종류별 공통 잠금, T0, cursor, 추가 변경분, 비교 승인, 마지막 성공을 기록합니다. 단순 ready와 운영 전환은 다릅니다.
- `academyDirectoryHistory`: 변경 전후 서버 전용 snapshot입니다. 연락처가 포함될 수 있으므로 client read/write를 모두 금지하고 내용 인덱스를 제외했습니다. 자동 TTL/클라우드 백업 설정은 하지 않았습니다.
- 기존 `notionStudentMappings`의 내부 ID·Firebase UID, `academyStudentMemberships`, `studentReportMappings`·`reportSlugs`를 대조합니다. 이름으로 연결하지 않습니다. 명시적인 canonical unlink는 기존 legacy 연결보다 우선합니다.
- `studentEnrollments`는 학부모 등 공개 조회용 projection입니다. 기존 저장본을 같은 ID로 재사용하고 새 원본 전체 사본을 공개 컬렉션에 추가하지 않습니다. 비공개 원본은 담당 관계·편집/복구 정보를 보관하므로 별도 역할입니다.
- 연결 없음·중복·다른 학원·미완료 앱 수정은 review로 남습니다. 계정/권한/리포트/PIN을 만들어 문제를 숨기지 않습니다.

## 읽기와 쓰기의 전환 경계

`academyCoreAuthority/main.active`가 전환 경계입니다. 전환 후에는 이 문서가 우선하며 `ACADEMY_CORE_MODE=notion`으로 바꾸더라도 오래된 Notion 경로로 자동 복귀하지 않습니다. 정상 앱 자료와 변경 이력을 먼저 보존합니다.

전환 전에는 기존 경로를 유지합니다. 관리자만 다음 작업을 수행합니다.

1. 관리자 설정의 **학생·선생님·수강 이전**에서 종류별 페이지 dry-run을 수행합니다. 읽기 전용이며 writes=0을 표시합니다.
2. 기존 계정/학원/원본/공개 저장본 연결 문제를 해결합니다. 한 요청에 원본 10개, 관리 목록 20개로 제한합니다. 전체 건수가 아니라 현재 페이지 결과입니다.
3. 최초 전체 → T0 이후 추가 변경분까지 가져오고 값/연결/보관 여부를 비교합니다. 종류별 검증 승인은 review가 남으면 거절됩니다.
4. **Notion 직접 수정을 중단**하고 최종 변경분을 다시 가져와 비교합니다. 최근 15분 안의 성공 기록, 잠금 없음, 미완료 수정 없음, 모든 종류 ready/승인을 확인합니다.
5. 반 연결이 있다면 반·시간표의 앱 전용 전환을 먼저 완료합니다. 연결된 반이 앱에 없거나 이 종류의 전환 확인이 없으면 진행하지 않습니다.
6. **최종 대조 후 앱 전용 전환**이 같은 트랜잭션으로 담당 관계와 기존 공개 수강 projection을 맞추고 전환 경계를 기록합니다. 이후 기존 세 원본의 import/reconcile은 거절하고 worker는 CORE_FROZEN으로 건너뜁니다.

이번 원자적 초기 전환은 종류별 100개, 선생님 100개, 합계 source payload 6MB 상한을 두었습니다. 초과 시 잘라서 이전하지 않고 중단합니다. 규모가 큰 학원은 분할 cutover 구현이 필요합니다. 일반 목록은 기존 전체 배열 계약을 보호하며 최대 500명 이후 오류를 냅니다. 관리자 이전 목록은 cursor 페이지입니다.

`ACADEMY_DIRECTORY_READ_MODE=notion`, `ACADEMY_DIRECTORY_SYNC_ENABLED=false`, `ACADEMY_CORE_MODE=notion`이 예제 기본값입니다. 운영 전환 문서가 없는 기존 설치는 원래 경로로 동작합니다. `ACADEMY_CORE_MODE=firestore`를 준비 없이 설정하면 오류로 멈추고 Notion으로 조용히 fallback하지 않습니다. 운영 이전/환경 설정은 이번 작업에서 실행하지 않았습니다.

## Firestore 운영 경로

| 기능 | 전환 후 |
| --- | --- |
| 학생 목록 | 기존 담당/학원 필터 뒤 Firestore 저장본. 브라우저 저장소 사용 없음 |
| 학생 상세/수정 | 같은 입력 schema/expected 시각 검사, 명령 ID와 버전 이력 |
| 보호자 연락처 변경 | 학생 값·PIN hash·authVersion을 같은 트랜잭션으로 갱신. URL·내부 ID·Firebase UID 보존 |
| 수강 조회/선택 옵션 | Firestore 학생/수강/선생님/이미 이전된 반만 사용 |
| 수강 수정 | 대상 과목만 수정. 다른 과목/공동 담당 보존, 공개 projection과 담당 scopes 원자적 갱신 |
| 담당 변경 | 기존 관리자/원장 제한과 assignmentRevision 검사. Notion PATCH 없이 관계와 scopes 저장 |
| 권한 검사 | Firebase 서명/폐기/계정 역할 + 현재 access/membership + Firestore scopes. 완료한 권한 결과를 영구 캐시하지 않음 |
| 리포트/문자 연락처 참조 | 전환된 학생의 최신 이름/연락처/PIN을 읽어 원본의 오래된 값으로 덮어쓰지 않음 |

기존 timestamp/실패 코드 일부는 호환을 위해 유지합니다. 실제 운영 버전은 appEditedAt/revision이며 출처 시각과 구분합니다. 중복 명령은 같은 의도만 받아들이며 오래된 요청은 최신 자료를 덮어쓰지 않습니다. 응답 재전송 시 현재 profile을 반환합니다. 변경되지 않은 다른 선생님의 scopes는 다시 쓰지 않습니다.

일지의 저장과 학부모 공개는 여기서 합치지 않았습니다. 일지/성적/일정의 Notion 의존 제거와 ‘반영’ 의미 분리는 해당 후속 구간에서 수행합니다. 반/시간표는 이후 앱 저장만으로 끝나도록 만들며 이번 묶음에서는 이를 완료했다고 주장하지 않습니다.

기존 신규 등록의 `sync-student-registration`은 전환 후 Notion에 새 자료를 생성하지 못하도록 명확한 미이전 오류를 냅니다. 초안은 유지합니다. 앱 전용 신규 등록은 다음 C-1 묶음에서 구현해야 합니다.

## 복구와 rollback

- 전환 뒤에는 Notion 조회로 단순 복귀하거나 authority active를 끄지 않습니다. 최신 앱 자료와 현재 connection metadata를 보존합니다.
- 마지막 정상 **Firestore 경로 지원 앱 버전**으로 복귀합니다. 이번 버전 이전 B는 그 경로를 지원하지 않으므로 전환 후 B를 단순 rollback 대상으로 쓰지 않습니다. 첫 전환 실패는 forward fix 또는 선택 복원으로 처리합니다.
- 학생 이름/연락처의 선택 복원 API `directory-restore-student`를 준비했습니다. 관리자·confirmed·현재 revision·historyRevision·operationId가 필요합니다. 원본 snapshot의 profile 필드만 재검증해 새 앱 버전으로 저장합니다. 계정/권한/반 연결을 과거 상태로 자동 복원하지 않습니다. 연락처 복원은 PIN/authVersion을 다시 정상 갱신하며 중복 요청은 두 번 갱신하지 않습니다.
- 광범위한 DB 복구는 별도 백업/PITR/분리 DB 복원과 대조가 필요합니다. 이번 작업은 이를 활성화하지 않았습니다.
- 양쪽 차이를 대조하지 않은 Notion 복귀나 app 자료 삭제/병합은 실행하지 않습니다.

## 검사와 측정

Notion 전달 함수를 차단하고, 실제 workspace actor 검사에서는 global fetch도 차단했습니다. Firebase token 검증과 Firestore는 모의 구현이므로 실제 클라우드/IAM 검증은 아닙니다.

검증: dry-run writes 0, 12건 cursor/catch-up, 기존 ID 재사용, 보호자 번호 변경 및 commit 실패, 명령 재전송·stale revision, 담당 삭제 즉시 권한 회수, 별도 과목/계정 보존, 반 전환 조건 거절, 선택 복원, UI mount 요청 0 및 관리자 노출, Node ESM 초기화입니다.

최종 검증 결과: lint 통과, 전체 테스트 607개 통과, build 통과, 일반 Node ESM workspace import 통과. 오래된 계정 snapshot의 권한 복구 방지, 활성 학생 누락 거부, 기존 학생 입력 schema의 전환 전 검증을 포함합니다. 실제 클라우드/브라우저 검증은 하지 않았습니다.

| 경로 | 기존 Notion 호출 | 전환된 시험 경로 |
| --- | --- | --- |
| 학생 상세 조회 | 학생 GET | 0 |
| 학생 정보 수정 | 원본/스키마 확인·PATCH·확인 | 0 |
| 수강 상세/옵션 | 학생·수강·선생님·반 조회 | 0 |
| 수강 상태/담당 수정 | 관계 확인·PATCH | 0 |
| 담당 권한 검사 | 선생님 GET + 수강 query 등 | 0 |
| 기존 리포트 학생 identity lookup | 학생 GET | 0 |

실시간/운영 지연과 Firestore RU/WU/비용은 미측정입니다. Firebase 계정 pair 외에 전환 checkpoint point read가 추가되며 동시 요청끼리만 공유합니다. 이 때문에 기존 resource-limit 테스트의 동시 읽기 기대값을 2→3으로 수정했고, 이후 비활성 계정 확인도 유지합니다. 계정/권한 결과를 오래 캐시하도록 검증을 완화하지 않았습니다.

## 다음 묶음

1. 반·정규 시간표·교재의 기존 Notion-only 자료 대조 및 canonical 이전.
2. 조회/수정/시간표 연결/학생 반 관계가 모두 Firestore에서 끝나게 구현.
3. 앱 전용 신규 학생 등록과 미이전 작업 처리.
4. 세 원본과 반 종류의 최종 변경분 대조 후 C-1 운영 전환을 검증.
5. 일정·일지·성적·문자·리포트의 나머지 의존 제거.

전체 누적 ZIP과 재개 기록을 전달한 뒤 다음 묶음 전까지 멈춥니다. 배포와 실제 화면 확인은 사용자에게 남깁니다. 문자 발송/Make 중단은 별도 승인 전 실행하지 않습니다.
