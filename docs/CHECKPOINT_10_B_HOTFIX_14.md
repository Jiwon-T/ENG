# 수업 일지 당일 여러 수업·재반영·숨김 보정

- 별도 앱 기록 ID는 같은 학생·날짜여도 독립된 Notion 페이지로 반영된다. 서버에 일일 1회 제한은 없으며 두 ID의 생성 테스트를 추가했다. 실제 오류 ID의 운영 로그는 접근하지 못했다.
- 여러 학생 작성에서 입력이 그대로인 미완료 반영 요청은 save-draft를 거치지 않고 기존 publish를 재시도한다. 새 내용으로 덮어쓰거나 불확실한 생성 요청을 복제하지 않는다.
- 완료된 Notion 원본을 재가져온 새 revision에는 이전 write journal을 이어 붙이지 않는다. 새 원본 baseline과 반영 revision을 일치시켜 수정 저장이 미완료 요청으로 오판되는 경로를 보정했다.
- Notion 원본에 정확한 앱 기록 ID가 있으면 해당 로컬 ID를 회수한다. 기존 미완료 일지는 import에서 덮어쓰지 않고 반환하여 기존 archive-lesson이 처리하게 한다. 진행 중 lease/확인되지 않은 Notion 생성 결과의 삭제 보호는 유지한다.
- 수업과 자습은 같은 날짜의 더 이른 시작 기록도 월별 회차의 기준으로 사용한다. 같은 시작 시간과 이후 기록은 제외한다.
- 저장된 일지는 단순 열기에는 회차를 유지한다. 시간/수업 유무/출결/날짜 변경 시 기존 회차에서 원래 증가량을 빼고 새로운 증가량을 더한다. 월이 바뀌면 0에서 시작한다. 직접 수정한 회차, 잘못된 시간, 직전 증가량을 계산할 수 없는 기록은 유지한다. 뒤의 다른 일지 회차를 일괄 변경하지 않는다.
- 오늘 수업은 예정·변경·완료 일정을 표시하며 취소는 제외한다. 정규와 보강은 다른 ID로 유지한다.
- X → 존댓말 확인 모달 → 네/아니오. 계정·날짜별 teacherTodayVisibility 서버 문서에 수업 ID만 저장한다. 학생 정보는 브라우저 저장소에 저장하지 않는다. 두 작성 화면 공유 및 새로고침 유지, 날짜 변경 독립, 복원 버튼 제공.
- 기존 일별 schedule-records 응답에 숨김 ID를 추가했다. HTTP 조회 요청 추가 없음. 일별 조회마다 Firestore 설정 문서 읽기 1회 추가. 숨김/복원 클릭마다 HTTP POST 1회 + 설정 문서 트랜잭션. Notion 요청은 추가하지 않는다.

## Notion → 앱 저장 전환 검토

현재 readMirroredPages는 서버 메모리 저장이 기본이고 Firestore 모드에는 1분 갱신/10분 전체 대조가 있다. 이는 화면이 Firestore만 읽고 변경분을 백그라운드 반영하는 구조와 다르다. 단순 플래그 전환은 조회 비용 및 삭제·권한 변경·오래된 값 덮어쓰기 문제를 해결하지 않는다.

다음 묶음은 학생 명단부터 시작해 원본 ID/원본 수정시각/앱 revision/삭제 표식/권한을 보존하는 최초 가져오기 및 동기화로 분리한다. 반·정규 시간표·교재 → 일정 → 과거 일지·성적 순서. 실제 계정의 Notion 호출 수, Firestore 읽기·쓰기, 로딩 시간 측정 전에는 일괄 운영 전환하지 않는다. 이번 수정에서 전체 자료 이전과 운영 설정 변경은 하지 않았다.

## 검증 범위

자동 회차, 재반영 요청 순서, 같은 날 두 독립 Notion 생성, 완료 보강 표시, 당일 숨김 서버 재조회·계정/날짜 분리·복원 테스트를 추가했다. 기존 오늘 수업 테스트는 완료 일정도 포함하는 새 동작에 맞춰 기대값을 변경했다.

운영 오류 ID 로그, 실제 Notion 반영·삭제, 실제 브라우저 상호작용은 확인하지 않았다. 기존 unknown write-result 삭제 차단은 안전을 위해 유지되므로 해당 경우는 반영 결과 대조 후 삭제해야 한다. 서버 숨김 문서는 날짜 범위 밖에서는 읽지 않으며 TTL 정리는 구성하지 않았다.
